# 领域包模板（中性起点）

读取同目录 domain.json。这里提供接口、检索词占位符和任务审查项；**它不是任何具体领域已完成提炼的知识库**。

**怎么用它：** 复制本目录到你自己的项目，改 `domain.json` 的 `id` / `scope` / `search_queries` / `project_parameters` / `checks` / `journal_candidates`，再改写本文件。领域包是可替换的配置，不是模型权重。

## 填参数的原则

`project_parameters` 里所有值默认是 `null`。填的时候只写**有确切依据的值**：

- 拿不到确切值就保持 `null`，不要写"约""典型值""一般情况"。
- 参数必须来自当前项目的数据说明或代码，不从别人的论文、旧项目或记忆里继承。
- 同一参数在不同项目里取值不同是正常的；跨项目复制时逐项重核。

## 变量与坐标

每个变量都要能回答三件事：**怎么定义、什么单位、在哪个坐标系或参考系里**。同一个物理量在不同命名体系下指的东西可能不一样，命名混用是最常见的错误来源。

记录坐标/参考系转换所用的库与版本，记录无效区，**不把无效值零填充或当成真实观测**。

## 数据源

核实真实的数据或仪器版本、采样方式、质量标记含义、覆盖范围与已知误差适用范围。不要从旧项目继承"精度上限"或"正常值"这类设定，先核验当前数据源的资料与代码。

## 量、基线与不确定度

公式、基线定义、窗口、分箱、平滑与子采样定义都须来自当前项目。记录基线误差与样本依赖。**样本标准差本身不是归因证据。**

识别可能的混淆来源（采样方式、周期性变化、背景漂移等），用匹配采样和真实对照去约束，而不是在文末机械地加限制句。

## 机制与因果

数据本身能支持的是明确的观测描述。机制解释要逐条检查可获得证据；**缺少关键变量时不得宣称测得相应的机制项。** 列出能区分不同机制的观测或分析，不预设唯一原因。

## 检查项

- [ ] 每个变量都有定义、单位、坐标系。
- [ ] 数据源版本、采样、质量标记已核实并记录。
- [ ] 基线定义与不确定度口径已写明，且来自本项目。
- [ ] 观测 / 关联 / 机制三层在措辞上分开。
- [ ] 混淆因素有处置，不是只在文末提一句。
- [ ] 缺关键变量时，机制结论的边界已写明。
- [ ] 没有硬编码的具体事件、阈值、幅度或个人画像。

## 边界

本包不包含任何预置研究结果，也不代表任何领域已获科学验证。所有结论由项目自身的真实数据和证据决定。候选期刊名一律用占位符，格式要求以目标期刊**官方作者指南**为准，不按印象核。
