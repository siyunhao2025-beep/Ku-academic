## 这个 Skill 到底做什么（直说，不绕）

**它是一个管住论文写作全流程的东西。** 你交稿，它按固定顺序跑；每一步都留证据，每一个数字都锁住。

具体是这些事：

| 直说 | 它到底怎么做的 |
|---|---|
| **你写论文最怕跑偏？** | 每一句话都回头对一遍全文核心主旨。结果段、结论段**强制**校验，没有共同锚点直接驳回重写。不是提醒，是拦下来。 |
| **润色把数字改了怎么办？** | 数字、单位、样本量、阈值、时间、仪器名全部**上红锁**。润色前后自动比对：丢了、改了、或者凭空多出一个数，**那一关直接驳回**。它算出来给你看，不靠模型自觉。 |
| **AI 在正文里写"我无法处理"？** | 第一关就拦。而且分得清"我研究的这个模型"和"我这个写作助手"——不会因为提到"模型"就误删你正文。 |
| **审稿人说你堆数据不讲意义？** | 一段里有两个以上数字、却没有一个字说明它们意味着什么 → 判为脱靶，退回重写。 |
| **压缩上下文把稿子压坏？** | 四个箱子分别设压缩上限，**结果箱一个句子都不许压**。压缩只生成**临时副本**，原稿永久存档、带哈希、改过就报错。**导出永远读原稿**，所以不可能压坏。 |
| **压完数字还在、定义没了？** | 这是最难发现的一类损坏。任何"定义红锁所涉及术语"的句子**自动升级为红锁**。定义句被删而术语还在用 → 校验失败。 |
| **结论没有文献撑着？** | 第五关专门盯结论箱的引用数量与贴切度。而且**只推荐你文献列表里已有的条目**，绝不编一条看起来像真的引用。 |
| **写引言怕抄到导师的句子？** | 只蒸馏**叙事骨架与段落递进逻辑**，输出框架不输出段落。摘抄同组导师原文是查重第一个抓的地方，这里直接禁掉。 |
| **上下文快爆了不知道？** | 80% 预警、90% 刹车。**但要提醒你：本工具读不到对话的 token 计量**，那四个数字必须你从平台用量页拿。缺一个它就说"无法判断"，不会拿估算值糊弄你——用编出来的数字触发的刹车比没有刹车更危险。 |

**它不做什么（同样直说）：**

- **不判断你的科学结论对不对。** 它保证流程完整、事实没被篡改，不保证结果正确。
- **不给录用概率。** 永远不给。
- **不替代你做语义判断。** 锚定和靶心用的是术语重合度做初筛，报告里明确写着这是启发式；真正"这句话有没有服务主旨"仍要你看。
- **不认识的红锁写法会漏。** 所以 `domain_keywords` 一定要填全。

一句话：**它是一条带护栏和审计日志的流水线，不是一个更聪明的聊天框。**

## 它帮你解决什么？

不是再收藏一堆互不相通的提示词，而是让下一步接住上一步的证据和产物。

| 你正在做的事 | Cool-Academic 的工作方式 | 应当留下的产物 |
|---|---|---|
| 开始一项研究 | 先读材料，分流原创研究或综述，梳理论点与证据 | 研究问题、项目状态、论点—图表—章节对应表 |
| 整理自己领域的经验 | 提炼文献与代码中的方法、适用条件、反例 | 有出处的知识卡、方法卡和测试用例 |
| 找新论文、写综述 | 按日期发现候选，再筛选、读全文、比较条件与结论 | 检索日志、证据矩阵、主题综合 |
| 核对引用是否真实可靠 | 身份与支持分开判定，阻断项单独列出，查不了的标待确认 | 引用溯源记录、阻断项清单、待确认清单 |
| 描述实验或分析过程 | 根据实际代码、配置和日志写 Methods | 方法—代码对应记录、可复现的描述 |
| 做科研图 | 线路图、原理示意图、数据图三类分开，保留处理与不确定度定义 | 源数据、绘图代码、图件、图注、配色逻辑 |
| 给已有文章补内容 | 只补有贡献的比较、方法依据、机制约束或纠错 | 有证据的修改方案与前后对照 |
| 学习目标期刊、润色英文 | 从同刊同体裁全文提炼论证和表达习惯，再检验应用效果 | 逐篇阅读卡、期刊风格档案、修订稿 |
| 让稿子读起来更像人写的 | 先锁死数字与证据强度，再改句式节奏 | 修订稿、交付前自查记录 |
| 想少花点 token | 默认精简档：复用已有产物，绝不砍掉数字、引用核验和图件审查 | 写明口径与方法的 token 台账 |
| 稿子写完了想先挨一顿批 | **3–5 位审稿人**各自独立打分，分歧不取平均 | 逐条评审意见、七维评分、不平均的分歧结论 |
| 想让不懂的人也能看懂 | 另出一份**讲解版 Word**，先打比方再上术语 | 真实 .docx，数字与论文逐项对齐 |
| 要出一张会议海报 | 先问**尺寸 / 语言 / 输出形式**，答完才动手 | 精确物理尺寸的矢量海报，或单页 PPT |
| 要做汇报幻灯片 | 走 `skills/ppt` 的完整设计系统与版式规则 | 幻灯片；**注意该技能有缺失依赖** |

**科学内容由承载 Skill 的模型基于真实材料处理；Python 脚本负责检索、编目、检查与打包。** 脚本不会凭空完成实验、自动造图造结果，也没有接入一个隐藏的付费模型服务。

## 优化来源

v0.2.0 的规则不是凭空写的。本次实际检索并读取了八个同类科研 / 学术写作 Skill 仓库，逐条记录它们的优点、不足，以及本项目吸收了什么、为什么吸收、写进了哪个文件。完整对比见 [同类 Skill 对比](docs/PEER_COMPARISON.md)，逐项改动见 [版本改动说明](docs/CHANGELOG_v0.2.0.md)。

其中三条最关键的判断：

1. **没有现成仓库同时做全四件事**——引用真实存在、引用确实支持这句话、数字不可被语言修改、部分通过不等于通过。本项目把两个最接近的来源融合成 [文献真实性](modules/evidence-integrity.md)。
2. **阶段阈值只能当工程下限。** 所有阈值都标注为可配置下限，并禁止用"调低阈值重跑一遍"把试运行标成正式验证。
3. **降 AI 必须先防止改坏科学。** 最有价值的单条结论来自一个同类仓库的警告：为降 AI 把 hedging 改成强断言，等于制造过度声称。

## 第一次使用：选一条路线

### A. 已经在 ChatGPT 连接 GitHub：直接开始

把下面这段发给 AI，无需先在电脑安装 Python：

```text
@GitHub 请读取 siyunhao2025-beep/Ku-academic 的根目录 SKILL.md，
再读取 modules/workflow.md 与当前任务需要的模块。
使用 research-mother，加载 example-domain 领域包。
根据我上传的文献、稿件、代码和结果，先建立项目状态和证据矩阵，再推进研究。
有实质证据才补稿，不堆防御性文字；缺少材料时继续能完成的步骤，不编造结果。
本次目标：[写原创论文 / 写综述 / 学习目标期刊 / 补稿 / 润色 / 描述方法 / 绘图]。
```

AI 必须实际读到仓库文件，而不是只看到仓库名称。这是**会话内按文件调用**，不等于已永久安装进账号；工具权限由当前平台决定。

### B. 想安装为 Skill：下载轻量包

进入 **[Releases 下载页](https://github.com/siyunhao2025-beep/Ku-academic/releases/latest)**，下载名为 `Cool-Academic-v<版本号>-skill.zip` 的附件（版本号以该页实际文件名为准）。它包含 `research-mother/SKILL.md` 及配套模块；不要把 GitHub 自动生成的 `Source code (zip)` 当成同一个安装包。

具有 Skills 上传权限的 ChatGPT 工作区：**Plugins → Skills → Create → Upload from your computer**，上传 ZIP，完成扫描并确认安装后，再说“使用 research-mother……”。没有该入口时，使用路线 A，或在支持文件与代码执行的对话中上传 ZIP、要求解压读取。以实际账号界面为准；GitHub 更新不会自动替换已上传副本。[官方安装说明](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)

### C. 想在电脑处理文件：运行本地工具

## 按什么顺序工作？

**六个阶段，所有任务共用。** 每个阶段都定义了输入、执行步骤、产出物和检查清单，见 [阶段总控](modules/phases.md)。

| 阶段 | 做什么 | 交什么 |
|---|---|---|
| P1 选题与论文调研 | 把大方向压成可判定的问题，做范围检索，建立术语表 | 研究问题、术语表、证据账本骨架 |
| P2 文献综述 | 多源检索、身份核验、支持核验、全文证据矩阵 | 检索日志、证据矩阵、研究缺口 |
| P3 实验设计 | 数据审计、假设、参数、匹配规则、替代设置 | 设计文档、混淆因素清单 |
| P4 计算与结果 | 实际执行、保留失败记录、跑稳健性检查 | 运行日志、结果文件、稳健性差异 |
| P5 图表与论文写作 | 线路图、原理图、数据图、各节写作、降 AI 自查 | 图表清单、论点对应表、稿件 |
| P6 结论与投稿返修 | 结论、引用终检、投稿自查、逐条回应 | 审查记录、回应信、投稿清单 |

**原创研究**  
问题与文献 → 设计与数据审计 → 实际计算与稳健性检查 → 图表 → 方法与结果 → 讨论与引言 → 摘要与结论 → 审查和润色。

**综述**  
范围与检索方案 → 检索和筛选 → 全文证据矩阵 → 比较结论与适用条件 → 主题框架 → 分节综合 → 引用核验和修订。

期刊风格学习可以提前做；不能让目标文风反过来改变研究结果。基线、参数或样本变化后，重新检查依赖它们的图件与段落。已登记文件依赖可由脚本检测失效，语义依赖仍需研究者或模型审查。阶段之间的通过条件与数值阈值见 [阶段闸门](docs/PHASE_GATES.md)。

## 四个特别的写作原则

**补稿是补论证，不是加免责声明。** 明确观测到的结果直接说清楚；机制证据不足时，只限定对应的机制句子。保留真正影响解释或复现的限制，不机械扩写泛泛的 limitations，不为增加引用数量而塞文献。

**学习期刊是学习表达组织，不是模仿作者或复制原句。** 从真实全文中提炼段落功能、量化方式、比较结构与图注职责；按期刊、体裁和作者组组织样本。没有读完语料，就没有完成风格学习；不以 AI 检测分数或投稿承诺作为验收标准。

**引用要过两道检，不是一道。** 第一道查这篇文献是否真实存在、出处是否准确；第二道查它是否真的支持你要它支持的那句话。DOI 能解析只说明第一道过了。判定值与硬阻断项见 [文献真实性](modules/evidence-integrity.md)；六类高风险错配（综述当原始实验、关联当因果、模拟当观测、范围不匹配、方向相反、二手来源给精确数字）出现任一类即按阻断处理。无法核实的一律标 `待确认`，并说明卡在哪一步。

**降 AI 痕迹的第一条是"什么不许动"。** 数字、单位、有效位数、符号、置信口径、仪器名、引用、证据强度一个字符都不改。为读起来更自信把"表明"改成"证明"，那不是降 AI，是制造过度声称。真正的杠杆是**句式节奏**：连续多个长度接近的句子要重组，而不是删几个副词了事。规则与交付前自查表见 [降 AI 模块](modules/deai-writing.md)。本 Skill 不承诺通过任何 AI 检测工具，也不提供绕过检测的方法。

## 图：一张路线图、一张原理图、一批数据图

每个研究任务默认产出三类图，各自回答不同问题，不能互相替代。

| 图 | 回答什么 | 关键约束 |
|---|---|---|
| 科研线路图 | 你从数据走到了哪个结论 | 每个形状都必须代表一个具名事物；计划版与实际版分开存 |
| 原理示意图 | 机制或方法长什么样 | 必须标为概念示意；观测/推断/假说三个层级要用视觉方式区分 |
| 数据图 | 数字是什么 | 不能只用颜色传信息，必须配形状或线型；色板选无障碍色板 |

配色逻辑、色差自检阈值、跨图一致性规则与图注写法见 [图的规则](modules/figures.md)。

## 精简模式：省 token，但不省科学

精简模式默认开启（`full` 档），纪律来自 [ponytail](https://github.com/obra/ponytail) 式的"最懒但真的能用"。一句话：**懒是指效率高，不是指马虎。**

**管什么：** 产出物数量、模块加载、重复读取、回复长度、工具调用次数、依赖引入。爬梯子顺序是"真的需要吗 → 项目里已有吗 → 标准库/现成脚本能做吗 → 能一句话吗 → 才动手写"。

**绝不砍什么：** 数字、单位、有效位数、符号、证据强度、引用的两道核验、`待确认` 标记、失败运行记录、数据审计结论、图件的人工视觉审查、隐私与授权、用户明确要求的东西。

判据只有一条：**省掉它会让结论更不可验证吗？会就不能省；不会就该省。**

三档强度：`lite` / `full`（默认）/ `ultra`。切换用 `/ponytail lite|full|ultra`，关闭用 `stop ponytail`。规则见 [精简模式](modules/lean-mode.md)。

### 每轮都会报一个 token 数，并且说明它是什么

```text
📊 累计 token（口径 A 写入量 · tiktoken:cl100k_base）：12,345
   对话本身 token：无法从本地读取 · 见 docs/TOKEN_ACCOUNTING.md
```

**第二行不能删。** 因为本工具测的是**文件产出物**的 token，不是**对话本身**的消耗——后者在当前宿主没有任何本地记录（已实际排查 `~/.claude/projects/`、WorkBuddy 日志目录，均不含本会话用量）。把一个不标口径的数字摆出来，等于让人以为那是账单。

两种口径：**A 写入量**（默认，改写重计，衡量成本）、**B 快照**（交付物当前体积，去重）。完整定义、估算公式、实测偏差与不可测量项清单见 [Token 统计口径](docs/TOKEN_ACCOUNTING.md)。

## 换个研究领域也能用

母 Skill 不绑定个人简历、具体研究事件、基线日期或某个固定结论。复制领域配置并在项目中替换，保持检索词、术语、检查项与已学知识卡相互分离。见 [领域包与架构](docs/ARCHITECTURE.md)。

目前 `example-domain` 是**起步接口和检查流程**，不是已经读完任一领域文献的知识库。目标期刊档案也需要你的真实语料来建立。

## 维护、隐私与许可

源自 Research Mother v0.1.0，现以 **Cool-Academic 独立仓库**维护，调用名保持 `research-mother`，当前版本 v0.5.0。五个上游项目通过 [版本清单](config/upstream.lock.json) 按需取用；登记或下载源码不代表全部原生安装与调用验收完成。没有默认开启后台文献订阅或自动投稿。

**第三方技能说明：** `skills/ppt/` 是一个**第三方**飞书幻灯片技能，逐字保留、不重写。它需要 `lark-cli`，且收到的合并文档只含 markdown —— 因此**缺 5 个 Python 工具与 2 个 XML 文件**，其中包含技能自己要求的强制静态校验步骤。**使用前必读 [缺失依赖清单](skills/ppt/MISSING_DEPENDENCIES.md)。** 本仓库不伪造这些文件。

论文全文、未发表稿件、科研数据和密钥留在私有工作目录。不要提交到这个公开仓库；忽略规则和打包清单也不能替代发布前核查。本项目原创代码与文档遵循 [MIT](LICENSE)，第三方技能、论文及素材保留各自许可。
