# Token 统计口径与展示形式

[返回首页](../README.md) · [精简模式](../modules/lean-mode.md)

**先说最重要的一句：本工具测的是「文件产出物的 token」，不是「对话本身消耗的 token」。** 这两件事完全不同，不能混报，也不能互相顶替。

为什么要把这句话放最前面？因为一个不标口径的 token 数字，几乎一定会被误读。用户看到"12,345"会以为那是账单上的数，实际上它只是产出物的体积。**把估算说成实测，就是本 Skill 明令禁止的那类错误。**

---

## 一、能测什么、不能测什么

| 项目 | 能否测量 | 说明 |
|---|---|---|
| 产出物文件的 token | ✅ **能，精确** | 装了 `tiktoken` 时用 `cl100k_base` BPE 实测 |
| 产出物文件的 token（无 tiktoken） | ✅ 能，**估算** | 用本文第三节的公式，偏保守（偏高） |
| 产出物的文件数、字节数、字符数 | ✅ 能，精确 | 直接读文件系统 |
| 读取过的源材料体积 | ✅ 能，精确 | 对读过的文件跑一次 `measure` 即可 |
| **对话本身的 token（输入 + 输出）** | ❌ **不能** | 见第二节 |
| 实际计费的 token 与费用 | ❌ **不能** | 只有平台侧有；本工具没有账单接口 |
| 模型内部推理消耗 | ❌ **不能** | 不对外暴露 |

### 一句话记住

**产出物体积 = 可以精确测量。对话消耗 = 必须去平台看。**

## 二、为什么对话 token 测不到（已实测排查）

不是没查，是查了没有。以下路径均已实际检查：

| 路径 | 检查结果 |
|---|---|
| `~/.claude/projects/**/*.jsonl` | 只有 **1 个**会话文件，时间 **2026-05-14**，与本会话无关。当前会话**没有**写入这里的记录 |
| `~/AppData/Local/WorkBuddy/logs/` | 3 个日志文件，最新为 **2026-08-31**，早于本会话；且是运行日志，不含逐轮 token 用量 |
| `~/AppData/Roaming/WorkBuddy/` | 空目录 |
| 本机 Python 环境 | `tiktoken` / `transformers` / `tokenizers` / `anthropic` / `openai` **均未预装**（`tiktoken` 由本次安装到隔离环境，仅用于文件计数） |

结论：**没有一份本地记录包含本会话的逐轮 token 用量。** 因此本工具把它报为 `not_measurable_from_here`，而不是猜一个数字填进去。

### 想要真实数字，去这两个地方

1. **平台用量页面** —— 当前对话的 token 用量与费用在宿主产品的用量/账单界面。这是唯一权威来源。
2. **`token-dashboard` 技能** —— 它读 `~/.claude/projects/` 的 JSONL 做成本分析。**注意适用范围**：它只对写入了该目录的 Claude Code 会话有效。本次排查显示 WorkBuddy 会话**没有**写入那里，所以它**读不到本次对话**。不要用它来顶替。

## 三、估算公式（无 tiktoken 时的降级路径）

本工具**不把 `tiktoken` 作为硬依赖**——为几行能做的事装一个带二进制扩展的包，违反精简模式自己的阶梯第 5 条。所以设计为"有则用，无则降级"，并且**每次输出都标明用的是哪条路径**。

### 公式

```text
tokens ≈ CJK字符数 × 1.05 + 非CJK字符数 ÷ 3.8
```

CJK 范围包含：CJK 标点（U+3000–303F）、假名（U+3040–30FF）、CJK 扩展 A / 基本区（U+3400–4DBF、U+4E00–9FFF）、兼容表意文字（U+F900–FAFF）、全角形式（U+FF00–FFEF）。

### 为什么不用简单的 `字节数 ÷ 4`

因为**中文和英文的 token 密度差三倍以上**。中文约 1 字 ≈ 1 token，英文约 4 字符 ≈ 1 token。一份中英混排的文档用 `bytes/4` 会严重低估。必须先按字符类别分开算再相加。

### 实测偏差（用 `SKILL.md` 对照）

| 方法 | 结果 | 相对误差 |
|---|---|---|
| `tiktoken:cl100k_base`（实测基准） | 1,767 | —— |
| `heuristic:cjk*1.05+other/3.8`（估算） | 2,208 | **+25.0%** |

**估算偏高，这是有意选的偏差方向。** 用于预算守卫时，偏高会让你更早警觉，偏低会让你在超支后才发现。

**但要知道它的局限：** `cl100k_base` 是 OpenAI 的编码，不是所有模型的编码。同一段文字在不同模型下的 token 数可以差 ±20%。所以即使标为"实测"，它的准确含义是"**在该 tokenizer 下实测**"，不是"该模型账单上的数"。这个区别在跨模型比较时必须说清楚。

### 方法标签

| 标签 | 含义 |
|---|---|
| `tiktoken:cl100k_base` | BPE 实测（在该编码下） |
| `heuristic:cjk*1.05+other/3.8` | 字符估算，偏保守（偏高） |

**这两个标签绝不能混着报，也不能省略。** 一个数字不带标签，等于没有信息。

## 四、累计口径的定义

**累计值有两种口径，含义不同，必须选一个并说明是哪一个。**

### 口径 A：写入量口径（默认，ledger 用这个）

**定义：** 每一步实际写入的产出物 token 之和。同一个文件被改写两次，计两次。

**含义：** 反映"为了产出这些文件，一共写了多少"。适用于衡量工作量与 token 成本。

**命令：**
```bash
python scripts/lean.py ledger <workspace> <step> --artifacts <文件...>
```

**为什么改写要重计：** 因为改写确实是新的输出消耗。若只按最终快照计，会低估多轮打磨的成本，而那恰好是最容易失控的部分。

### 口径 B：快照口径

**定义：** 交付目录当前全部文本文件的 token 之和，去重，不累计历史。

**含义：** 反映"这个交付物有多大"。适用于衡量交付体积。

**命令：**
```bash
python scripts/lean.py measure <目录> --root <目录>
```

### 两者的关系（注意：不能无条件相减）

**先明确：两个口径统计的是不同的文件集合。**

| | 口径 A 写入量 | 口径 B 快照 |
|---|---|---|
| 统计对象 | 被记录的那些步骤里**实际写入**的文件 | 目录里**当前存在**的全部文本文件 |
| 文件集合 | 只含本次写入过的 | 含原有的 + 新增的 + 未改动的 |

因此：

```text
先把口径 B 限定到与 A 相同的文件清单，再比较 —— 这时 A ≥ B，差值就是重复改写量。
不限定就直接相减 —— 没有意义。
```

**为什么不能直接相减：** 如果项目里原有文件很多、本次只改了几个，B 会**大于** A。这不是错误，是集合不同。本次实测就出现了这种情况：A = 88,406，而全目录 B = 97,375，因为 B 还包含了仓库里原有的 20 多个文件。

**要看返工量，用这个做法：** 对同一个文件清单分别取 A 与 B（同集合），差值是重复改写量。差值越大，说明改的轮次越多。

**要看交付物多大，用这个做法：** 用 B 报全目录。本仓库交付物的实测值为 **97,375 token / 52 个文本文件**（`tiktoken:cl100k_base`）。

### 明确不计入的部分

| 不计入 | 原因 |
|---|---|
| 对话输入（系统提示、工具返回、文件读取） | 无法测量；且它通常是成本大头 |
| 对话输出（我的正文回复） | 无法测量 |
| 模型推理 | 无法测量 |
| 二进制附件（PDF、图片、NetCDF） | 不是文本，token 口径不适用 |

**因此 ledger 里的累计值是一个「产出物成本的代理指标」，不是总成本，更不是账单。** 它在同一项目内跨步骤比较是有意义的；跨项目或跨模型比较没有意义。

## 五、展示形式

### 规定格式

每轮回复末尾附两行，不许多附：

```text
📊 累计 token（口径 A 写入量 · tiktoken:cl100k_base）：12,345
   对话本身 token：无法从本地读取 · 见 docs/TOKEN_ACCOUNTING.md
```

### 硬性要求

1. **必须标口径**（A 写入量 / B 快照）。
2. **必须标方法**（`tiktoken:...` 或 `heuristic:...`）。
3. **必须保留第二行。** 即使数字不好看、即使显得啰嗦，也不许删。删掉它就等于让读者以为"那个数就是全部"，而这正是本模块要防的误读。
4. **不可测量的项写"无法测量"**，不许用估值冒充实测，也不许省略。
5. 数字用千分位（`12,345`），便于人眼读。
6. 数字每轮更新；无法重算时保留上一次的值并注明"未更新"。

### 单步骤展示（不是全程）

只报某一步时，格式：

```text
本步 +1,234 → 累计 12,345（口径 A · tiktoken:cl100k_base）
```

### 汇报给他人时

**必须**带上口径与方法。示例：

> 本项目产出物累计约 1.2 万 token（口径 A 写入量，`tiktoken:cl100k_base`）。对话本身的用量请以平台用量页为准，本工具读不到。

**不许**写成：

> 这个项目花了 1.2 万 token。

后者把产出物体积说成了总消耗，是错误陈述。

## 六、ledger 文件结构

`audit/token-ledger.json`：

```json
{
  "method": "tiktoken:cl100k_base",
  "scope": "artifact_files_only",
  "conversation_tokens": "not_measurable_from_here",
  "cumulative_tokens": 0,
  "entries": []
}
```

每条 entry：

```json
{
  "step": "P5",
  "ts": "2026-09-17T13:45:00+00:00",
  "artifacts": [{"path": "manuscript/draft.md", "bytes": 8123, "chars": 7011, "tokens": 3900}],
  "subtotal_tokens": 3900,
  "cumulative_tokens": 3900,
  "note": ""
}
```

**`conversation_tokens` 这个字段是有意留在每条记录里的。** 它时刻提醒读者：这份账只记了一半，另一半不在这里。删掉它会让文件读起来像一份完整账目。

## 七、命令速查

```bash
# 测文件或目录（快照口径）
python scripts/lean.py measure runs/my-study/manuscript --root runs/my-study

# 强制用估算（验证降级路径，或无 tiktoken 环境）
python scripts/lean.py measure SKILL.md --heuristic

# 记一步（写入量口径，会累加）
python scripts/lean.py ledger runs/my-study P5 --artifacts manuscript/draft.md --note "初稿"

# 看累计
python scripts/lean.py report runs/my-study

# 机器可读
python scripts/lean.py report runs/my-study --json
```

退出码：`0` 正常，`2` 出错（与 `scripts/research.py` 一致）。

## 八、这份口径不许做的事

- **不许把估算标成实测。** 方法标签就是为此存在的。
- **不许省略"对话 token 无法测量"这一行。** 省略即误导。
- **不许用产出物数字推断账单。** 两者之间没有可换算关系。
- **不许多重计数后不声明。** 用口径 A 就必须说"含重复改写"。
- **不许在跨模型比较时假装 token 数可比。** 不同 tokenizer 不可直接比。
- **不许让这行统计挤掉实质结论。** 它是脚注，不是主角。如果它让回复变长到影响阅读，说明放错了位置。
