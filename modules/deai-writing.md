# 降 AI 痕迹：先保证不改坏科学，再谈像不像人写的

[返回首页](../README.md) · [阶段总控](phases.md) · [交付前自查表](../assets/deai-checklist.md)

---

> ⚠️ **重要伦理声明（先读这个）**
>
> 这个模块的作用是让**你自己写的、有真实数据和结论支撑的**论文读起来更自然、更符合学术写作规范，**不是帮你绕过AI检测工具，也不是帮你把AI写的内容伪装成人写的**。
>
> 1. 任何声称"100%绕过AI检测"的工具和方法都是骗人的，检测技术一直在更新，没有一劳永逸的方法。
> 2. AI的正确用法是：你有想法、有数据、有结论，AI帮你润色语言、整理逻辑、检查错误；不是让AI替你想、替你做、替你写。
> 3. AI辅助写作的范围，必须按照你目标期刊和学校的要求**如实披露**，不要心存侥幸。
> 4. 学术不端的后果是你自己承担，这个工具不会、也不可能帮你规避责任。
>
> 【导师说】我不反对用AI提高效率，我反对的是骗。踏踏实实做研究，AI是好工具；想着怎么蒙混过关，迟早出事。

---

**第一件事不是"怎么改得像人写的"，而是"什么绝对不许动"。**

先打个比方。

**像给照片磨皮。** 你可以把噪点磨掉，让脸看起来自然。但你要是一把磨掉痣、疤痕和皱纹的位置关系，那已经不是这张脸了。降 AI 痕迹也是这样——改的是**说话的节奏和方式**，不是**数字、结论和证据强度**。

**改坏科学的降 AI，比明显的 AI 味更严重。** 后者只是不好看，前者是学术问题。

---

## 一、红线：这些内容一个字符都不许改

润色前先把下面这张表读一遍。表里的东西，无论句子里有多少 AI 味，都不许动。

| 不许动 | 具体指 |
|---|---|
| 数字 | 数值、样本量、时间、日期、比例、坐标、分箱边界 |
| 单位 | 单位名称与量纲，包括单位换算关系 |
| 符号 | 正负号、不等号方向、上下标 |
| 有效位数 | 3.14 不能改成 3.1，1.20 不能写成 1.2 |
| 置信口径 | SD / SE / CI / 显著性水平，以及它基于什么样本单位 |
| 仪器与产品名 | 仪器型号、数据集版本、坐标系统名称 |
| 引用 | 引用位置与引用编号 |
| 证据强度 | `suggest` / `indicate` / `demonstrate` / `is consistent with` 的层级 |

### 反过度纠正（最重要的一条）

**不能为了"读起来更自信"把弱表述改成强表述。**

把
> The results **suggest** that X.

改成
> The results **prove** that X.

这不是降 AI，这是**制造过度声称**。审稿人一眼就会抓，而且这是性质问题。

同样，以下几种"改坏"要避免：

- 把证据支持的 hedging（`may`、`appears to`、`is consistent with`）删掉，读起来更"利落"——不允许。
- 把被动语态一律改成主动——有些领域惯例就是被动，改掉反而不专业。
- 把 "we" 一律删掉——很多期刊明确要求用 we。
- 把领域术语换成通俗说法——准确优先于好读。

**判定口诀：如果一个改动让结论看起来更强，但没有新证据支持这个增强，就不能改。**

## 二、清晰度优先：先补齐关系，再调整句界

句长、句长方差或检测器分数没有跨作者、跨语言、跨学科通用的“人类阈值”。相似句长本身不是缺陷，刻意制造长短起伏也不会自动让文字更自然。判断标准是：读者能否一次读清楚谁做了什么、比较了什么、在什么条件下成立，以及哪条证据支持哪句话。

按下面顺序处理：

1. 先找含义缺口：主语/对象不明、代词无明确指代、比较对象缺失、条件堆叠、抽象动词没有说清实际变化。
2. 查证据后补齐必要关系；原稿没有的信息标 `待确认`，不能为了句子顺滑自行补造。
3. 删除只复述上一句的预告和总结，但保留新增机制、比较、限定或解释。
4. 只有在能减轻理解负担时才拆句或合句。清楚的短句保持短；承载一个完整比较或条件链的长句也可以保留。

中文可用逗号节律、连续同构句、空泛名词化和指代距离作为**定位信号**，但必须回到具体上下文判断。出声读只帮助发现拗口，不证明文本由谁生成。

## 三、模式信号不是硬配额

下面这些现象值得复查，但不存在通用计数上限：

| 定位信号 | 要问的问题 | 处置 |
|---|---|---|
| 高频套话重复 | 是否承载了具体对象、数据或逻辑关系？ | 无信息则删；有功能则保留或具体化 |
| 段末总结 | 是否只换词复述，还是加入了必要解释？ | 只删重复，不删实质推断 |
| 排比或同构句 | 是否帮助并列比较，还是为了显得完整？ | 按论证功能决定，不按数量决定 |
| 冒号、破折号、加粗 | 是否符合目标语言、期刊和文档结构？ | 修正滥用，不机械清零 |
| 模糊归因 | 能否定位到真实来源？ | 无来源即阻断并标 `待确认` |
| 模糊结尾 | 是否明确剩余不确定性或下一项可检验问题？ | 改成具体边界，或删除空话 |

不设“噪声预算”，也不故意保留所谓 AI 特征。目标不是优化检测器或模仿随机性，而是在不改变科学含义的前提下，让表达清楚、具体、连贯并符合作者与期刊语体。

## 四、句式与结构层面的操作

### 要拆掉的

| 模式 | 表现 | 怎么改 |
|---|---|---|
| 机械排比 | 三个以上结构完全相同的短句并列 | 留两个，第三个改成不同结构或并进前句 |
| 均匀句长 | 连续句子长度接近 | 长短交替，见第二节 |
| 空泛名词化 | "对……进行了分析""实现了……的提升" | 换成具体动词："分析了""提高了 12%" |
| 三段式套话 | "首先……其次……最后……" 每段都用 | 换成内容驱动的衔接，或直接不用连接词 |
| 万能过渡 | "综上所述""值得注意的是""需要指出的是" | 删掉，让前后句自己衔接 |
| 抬头式开场 | "在当今……的背景下" | 直接说事 |
| 结尾升华 | "为……提供了新的思路""具有重要的理论和实践意义" | 删掉，或用具体结论替代 |
| 对称收尾 | 每段都有一句总结 | 大部分段落直接结束在事实上 |

### 要加上的

| 做法 | 说明 |
|---|---|
| 长短句交替 | 见第二节，这是主力手段 |
| 具体化 | "显著提高"→"提高 12%（n=48）" |
| 强动词 | "进行了测量"→"测量了" |
| 与最强对手比较先行 | 讨论时先比最像的、最强的前人结果，再比其他的 |
| 区间优先 | 除非说明了平均方法，否则给区间而不是单个均值 |
| 信息位置正确 | 上一句结尾提供的信息，成为下一句的开头 |

## 五、自查：交付前必跑

润色完成、准备交付之前，按顺序回答下面这些。**每一题都要真的回答，不是打个勾。**

详细版本见 [交付前自查表](../assets/deai-checklist.md)。

### 证据层（先做这一层）

1. 有没有哪句话在润色后变得比原稿更强？逐句核对证据强度词。
2. 数字、单位、有效位数、符号、引用有没有被动过？（建议用工具做字符级 diff）
3. 有没有新出现的因果表述，而原稿只是关联？
4. 有没有把"计划"写成"已完成"？
5. 术语有没有被换成不同义的词？

### 语言层

6. 主语、对象、比较项、条件和指代是否无需猜测？
7. 拆句或合句是否真的降低了理解负担，而不是机械制造长短差？
8. 段末句是否增加新信息；若只是换词复述，是否已删除？
9. 排比、冒号、破折号与加粗是否各自承担清楚的结构功能？
10. 有没有无出处的归因？
11. 有没有为了换“更自然”的词而破坏术语一致性？
12. 结尾有没有空泛升华；必要限制和下一项可检验问题是否说具体？
13. 有没有任何改动只为了检测器分数、词表命中数或句长配额？有则撤回并重做语义审查。

### 冷读（最后一关）

暂时忘掉上面所有规则，只回答：

- 哪里让我相信作者确实做过这件事？
- 哪里让我愿意继续读？
- 哪一段像人在处理一个问题，哪一段像机器在完成任务？
- 哪句话说得比证据大？
- 文章在哪一句其实已经结束了？

**如果最后一问的答案是"最后两段都可以删"，就删掉。**

## 六、规则冲突时怎么排

同一句同时触发多条规则时，按下面的优先级裁决，不要凭感觉。

1. **数字、单位、符号、引用、证据强度** —— 最高，任何情况下不动。
2. **领域术语与惯例**（被动语态、`we` 的用法、单位习惯）—— 高于语言风格偏好。
3. **期刊官方要求** —— 高于本模块的一般建议。
4. **清楚与准确** —— 高于"读起来像人写的"。
5. **节奏与用词的自然度** —— 在以上都满足的前提下优化。

**冲突时的默认动作：保留科学内容，牺牲风格收益。** 宁可留一点 AI 味，不要改坏一个数字。

---

## 七、边界

- 本模块的目标是**让表达更准确、更自然、更可读**。
- **不承诺通过任何 AI 检测工具**，也不提供"绕过检测"的方法。检测分数不是质量标准。
- 不把句长、标点、套话或所谓“轻度特征”数量当作作者身份判定或交付门槛。
- **不隐藏必要的 AI 使用声明。** 如果目标期刊要求披露 AI 辅助，如实披露，披露文本照期刊要求写。
- **不使用生成式工具重写科学结论。**

## 与其他模块的关系

- 段落逻辑先行：`modules/writing-review.md` 的"问题—证据—比较—机制范围"结构。
- 引用与数字的核对：`modules/evidence-integrity.md`（改句之后引用位置可能移动，要复查）。
- 期刊风格档案：`modules/journal-distillation.md`。学的是修辞动作，不是抄句子。
- 用户若已有自己的中文写作规范技能，两者取并集，冲突按第六节裁决。
