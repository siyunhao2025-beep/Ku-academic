# 第五关 · 参考文献校验与引用布控

[返回首页](../README.md) · [写作总调度](paper-orchestrator.md) · [文献真实性](evidence-integrity.md) · 脚本：`scripts/gates.py`

**目标：解决三类引用问题。**

1. 文中引用与段落论述**不匹配**，引文放的位置不对；
2. **格式错误**、序号错位；
3. **结论部分引文偏少**，结论段缺少贴切的文献支撑。

这一关做两件事：**引文校验** + **结论章节引文布控**。

---

## 一、第一步：引文合规校验

| 检查 | 判定 |
|---|---|
| 引用的文献是否和这句话讨论的内容匹配 | 不匹配 → 标记失效，给出替换建议 |
| 引用格式是否统一 | 标记序号错位、文献信息不匹配 |
| 引用的 key 是否存在于文献列表 | **不存在 → reject** |

**禁止引用无关文献，不能强行堆砌。**

⚠️ **只推荐清单里已经存在的文献。** 这一关**永不编造**新文献。它的"推荐"是把列表里**已经有的、与项目方向匹配的**条目挑出来，告诉你可以放在哪里——不是生成一条看起来像真的的引用。

真正的身份与支持核验（这篇文献是否真实存在、是否真的支持这句话）由 [文献真实性](evidence-integrity.md) 负责，本关不重复也不替代它。

---

## 二、第二步：分章节差异化引用布控

| 箱 | 引用策略 |
|---|---|
| **引言箱** | 沿用引言蒸馏模块的引用逻辑，保留综述类文献 |
| **数据箱、结果箱** | 按需匹配文献，验证仪器、数据方法相关引文的贴切性 |
| **结论箱** | **重点布控**（见下） |

### 结论箱：重点布控

通读结论段落，识别出这几类内容：

- 讨论的科学发现
- 与前人工作的对比
- 研究局限
- 未来展望

在适合的位置补充**高度贴合主题**的参考文献。要求：

- 新增引用**不能生硬堆砌**，必须用来支撑结论的论述；
- 优先用于**对比本结果与前人研究**，或**说明本研究局限**；
- **每一处引用都要有对应的逻辑理由**。

脚本判据：结论箱总引用数低于配置的最小值（默认 2）→ `flag`，并提示"在对比、局限或展望句补充"。这个最小值可用 `--min-conclusion-citations` 调整。

### 方向匹配是可配置的，不是写死的

`citation_domain_keywords` 是**项目级配置**。本仓库保持通用，你自己的方向填自己的关键词；推荐逻辑只在这个范围内挑**已存在**的文献。

> 早期版本曾把某个具体研究方向的关键词直接写进仓库。这既让技能绑定了一个领域，也暴露了作者的研究方向，已改为项目级配置。

---

## 三、硬性约束

| # | 约束 | 实现 |
|---|---|---|
| 1 | **不能编造不存在的文献**，推荐补充的文献必须真实可检索 | 只推荐列表已有条目；未知 key 直接 reject |
| 2 | 新增引用不能强行塞进句子、不能破坏原句语义 | 本关不改写句子，只给布设位置建议 |
| 3 | 结论部分增加引文优先选择与本课题高度相关的文献 | 由 `citation_domain_keywords` 决定 |
| 4 | 引用数量合理，不要无限制堆砌 | 给出最小值下限，同时报告实际数量供人判断 |

## 五、检查清单

- [ ] 每个引用的 key 都在文献列表里存在。
- [ ] 引用位置与所支撑的论述匹配，没有"引了但说的不是一回事"。
- [ ] 结论箱的引文数量达到配置下限，且**每条都能说出理由**。
- [ ] 补的引用来自列表已有条目，**没有一条是生成的**。
- [ ] 没有为了凑数而堆砌引用。
- [ ] 引用身份与支持核验已在 [文献真实性](evidence-integrity.md) 中独立完成（本关不替代它）。
