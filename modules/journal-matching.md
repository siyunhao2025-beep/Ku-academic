# 目标期刊选择：证据分层，不预测录用

这个模块解决“稿件已经成形，但目标期刊还没定”的问题。它与两个相邻模块分工明确：

- `journal-sourcing.md`：期刊已经确定，获取同刊论文；
- `journal-distillation.md`：期刊已经确定，从全文学习写作组织；
- 本模块：从稿件与作者约束出发，形成可审查的候选短名单。

它不输出录用概率，不用影响因子或总排名代替适配判断，也不把“数据库未收录”写成期刊不合格。

## 输入与产出

输入至少包括稿件工作标题、拟投文章类型、主题/方法关键词和作者的真实约束（例如开放获取、费用、篇幅、时限或预印本政策）。没有稿件或结构化摘要时，先返回 P5 补齐材料，不能靠关键词替稿件选刊。

产出：

- `journal-match.json`：检索、论文证据、官网核验与约束账本；
- `audit/journal-match.json`：确定性契约检查；
- 面向作者的四档短名单：`strong_fit / plausible / stretch / blocked`。

## 执行流程

### 1. 先锁定稿件，不先列“名刊”

从稿件提取研究对象、核心问题、方法、最强结果、文章类型和不能妥协的约束。期刊声誉、熟悉度和总引用量不能替代这些字段。作者尚未确认的约束保留为 `unknown`，不得猜成满足。

### 2. 用多个渠道建立候选池

至少记录查询式、来源、带时区时间、结果上限和命中数。候选信号可来自：

- `bibliography`：稿件中真正相关的参考文献发表去向；
- `recent_similarity_search`：近年相似问题、方法或结果的论文；
- `citation_neighbor`：已核验核心论文的前向/后向引文邻居。

论文证据必须有题名、已核验发表期刊、年份和 DOI/PMID/稳定链接；发表期刊必须与当前候选一致。题名或摘要相似只是候选信号，不等于期刊已经适配。

### 3. 回到期刊官网核验

对每个候选分别核验 scope 与目标文章类型；需要满足的费用、开放获取、篇幅、时限或预印本政策也逐项核验。正式结论保留官网 URL 与检查时间；聚合网站只能帮助发现，不能替代官网事实。

如果官网明确 scope 不符、文章类型不接收，或任一不可妥协约束冲突，候选必须进入 `blocked`。无法核验写 `unverified/unknown`，不能静默通过。

### 4. 分档，不做伪精确评分

- `strong_fit`：至少两篇定位明确的论文，且来自两个独立发现渠道；官网 scope 为 `fit`、文章类型为 `accepted`，所有已声明约束均已核验且无未知项。
- `plausible`：至少一篇定位明确的论文，没有官网不符或约束冲突，但证据链尚未达到 strong 的工程下限。
- `stretch`：主要依赖研究者判断，或官网/论文证据仍有关键未知；明确写出需要补查什么。
- `blocked`：已有官网不符、文章类型不接收或作者约束冲突。

以上是短名单工程门槛，不是统计模型，也不表示编辑判断或录用可能性。

### 5. 运行契约检查

```bash
python scripts/journal_match.py init journal-match.json
python scripts/journal_match.py check journal-match.json --out audit/journal-match.json
```

检查器拒绝：搜索覆盖不可复核、候选重名、论文证据缺定位、官网结论缺 URL/时间、冲突候选未进 blocked，以及 `acceptance_probability`、自动加权分等字段。它不联网查期刊、不判断声誉或掠夺性、不测量 scope 的语义正确性，也不替作者选择最终去向。

## 交付给作者

按四档列出期刊、稿件特征与期刊证据的对应关系、满足/冲突/未知约束和下一步。只主动推荐 `strong_fit`；没有 strong 时如实给出需补查项或稿件—期刊取舍，不把 stretch 包装成高匹配。

最终选择需要作者确认费用、周期、开放获取和职业/机构政策。选择后再进入 `journal-sourcing.md` 与 `journal-distillation.md`，期刊变化则按 `change-management.md` 传播到格式、篇幅、结构与投稿材料。
