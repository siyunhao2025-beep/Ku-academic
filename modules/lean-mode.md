# 精简模式：省 token，但不省科学

[返回首页](../README.md) · [Token 统计口径](../docs/TOKEN_ACCOUNTING.md) · [阶段总控](phases.md) · 来源：[同类对比](../docs/PEER_COMPARISON.md)

**这一模块的纪律来自 `ponytail` 技能**（"最懒但真的能用"的解法），把它从写代码迁移到做科研流程上。核心一句话：

**懒是指效率高，不是指马虎。最好的产出，是没有被生产出来的那部分。**

先打个比方。

**像出差装箱。** 你要带的东西很多，但箱子只有一个。省 token 不是把牙刷留在家，而是别带三套西装去开一天的会。**该带的一件不少，不该带的绝不带上。** 判断标准只有一条：少了它，这趟差就办不成事。

---

## 一、触发方式

| 方式 | 怎么写 | 效果 |
|---|---|---|
| 全程显式调用 | 对话开头写 `@skill:ponytail` | 本会话每一轮都生效，默认 **full** 档 |
| 技能内触发词 | `精简模式` / `省点 token` / `别过度设计` / `最短路径` / `lazy mode` / `YAGNI` / `do less` | 同显式调用 |
| 指定档位 | `/ponytail lite`、`/ponytail full`、`/ponytail ultra` | 切换强度 |
| 关闭 | `stop ponytail` / `normal mode` | 立即退出，回到默认行为 |
| 领域包继承 | `domain.json` 里写 `"lean_default": "full"` | 该领域默认开启（可选，需自行加） |

**默认档位是 `full`**，不带参数时按 full 执行。档位一旦设定，持续到被改变或会话结束，**不会自行漂移**。

### 三档强度

| 档位 | 行为 |
|---|---|
| **lite** | 照要求做，但用一句话点出更省的做法，由用户决定 |
| **full**（默认） | 阶梯强制执行。先查现成的，再写新的。最短产出、最短说明 |
| **ultra** | YAGNI 极端派。先删后加。能一句话解决的就不写一段，并同时质疑需求里剩下的部分 |

例：用户说"给这个检索流程加个缓存层"。

- **lite**：已加。顺带一提，`functools.lru_cache` 一行就能覆盖，你要是懒得维护缓存类可以用它。
- **full**：在抓取函数上加 `@lru_cache(maxsize=1000)`。跳过自建缓存类——等 `lru_cache` 实测不够用了再说。
- **ultra**：profiler 没说话就不加缓存。真要加：`@lru_cache`。手写的 TTL 缓存类是一个带命中率的 bug 农场。

## 二、生效范围

**管的是"造什么"，不管"怎么说话"。** 精简 ≠ 敷衍，输出该有的结论、风险提示、验收结果一样不少。它管不住也不该管你的语气。

### 管这些

| 范围 | 具体含义 |
|---|---|
| 产出物数量 | 不为"以后可能用得上"多建一个文件、多画一张图 |
| 模块加载 | 只读当前任务真正需要的模块，不一次性把所有模块读进来 |
| 重复读取 | 同一个文件不重复读；已知内容不重复索取 |
| 回复长度 | 结论先给，细节进文件。回复不搬运文件内容 |
| 工具调用 | 单个脚本调用能完成的事，不用五个 |
| 中间产物 | 不把未验证的草稿、临时统计、过程日志写进交付目录 |
| 依赖引入 | 能用标准库解决的不引第三方；**本模块自己就遵守这条**（`tiktoken` 是可选增强，不是硬依赖） |

### 绝不可精简（这是本模块的红线）

精简模式**永远不许**削减下面任何一项。这些相当于 ponytail 说的"信任边界的输入校验、防止数据丢失的错误处理"——在科研场景里它们是同等地位。

| 不许省 | 为什么 |
|---|---|
| 数字、单位、有效位数、符号 | 省掉就是学术错误 |
| 证据强度 | 把"表明"简成"证明"是制造过度声称 |
| 引用的身份核验与支持核验 | 见 `evidence-integrity.md`，这是不可跳过的两道检 |
| `待确认` 标记 | 查不到就要说查不到，不能省成"没问题" |
| 失败运行的记录 | 省掉等于隐藏选择性报告 |
| 数据审计结论 | 审计不通过就不能进下一步 |
| 图件的人工视觉审查 | 不能凭"文件存在"说通过 |
| 隐私与授权 | 私有材料不进公开仓库；投稿需授权 |
| 用户明确要求的东西 | 用户要完整版就给完整版，不再争 |

**一条判据：** 如果省掉某一项会让结论变得更不可验证，就不能省。反过来，如果省掉它只是让产出更少、更短，而结论强度不变，那就该省。

## 三、阶梯：先爬再写

停下在第一个能站住的台阶上。

1. **这一步有必要存在吗？** 只是"以后可能有用"→ 跳过，用一行说明理由。
2. **项目里已经有了吗？** 先找现成的模块、脚本、模板、已有产出。**重复造已有的东西是最常见的浪费。**
3. **标准库能做吗？** 能就用。
4. **现有工具/平台已经覆盖了吗？** `research.py check` 能查的依赖，不要手工列；`corpus.py` 能做的编目，不要手写。
5. **已经装了的东西能解决吗？** 不为了几行能干的事装新包。
6. **能一句话说清吗？** 那就一句话。
7. **到这一步，才** 写能用的最小版本。

**阶梯是反射，不是调研项目。** 但它在**理解问题之后**才跑，不是代替理解。先读任务和它碰到的文件，把真实流程走通，再爬梯子。**懒不能省掉理解**——跳过理解去交一个短小的产出，是最危险的那种懒，因为它看起来像效率。

### 科研场景的落地

| 情形 | 省的做法 | 不省的部分 |
|---|---|---|
| 写综述 | 复用已有证据矩阵的结构，不重建字段 | 每篇文献的身份与支持核验照做 |
| 补稿 | 只补真正缺论证的地方，不批量贴引用 | 每条修改的证据出处照给 |
| 画图 | 复用已锁定的配色与形状词汇 | 三类图该出的照出；数据必须来自真实结果 |
| 写 Methods | 逐条关联代码位置，不复述代码全文 | 实际运行过的操作都写全 |
| 找文献 | 先跑一次定向检索，不铺开全网 | 检索日志、截断与失败照记 |
| 回答用户 | 结论 + 下一步，细节进文件 | 阻塞项与风险照说 |

## 四、省 token 的具体动作

这一节是可执行清单，不是原则。

### 读

- **只读需要的模块。** `SKILL.md` 的路由表已经指明意图 → 模块，按表读，不要全量加载。
- **不重复读同一个文件。** 已经读过的内容不再索取；需要核对时用定向搜索而不是整文件重读。
- **大文件的局部读取。** 需要某一段时用偏移量读，不要整篇拉进来。
- **搜索优先于遍历。** 找符号、找引用一律用 `Grep` 定位，不要靠逐个文件读。

### 写

- **一次成文。** 同一份产出不要反复小改多轮。
- **不重发未变内容。** 只输出差异段落，不要整篇重贴。
- **回复与文件分工。** 回复给结论与下一步；长内容进文件，让用户自己看。
- **不写"过程性"文件。** 只有会被下游消费的产物才落盘。

### 工具调用

- **合并独立的调用。** 能并行的并行，能一次脚本完成的不要拆多次。
- **结果写文件再读。** 输出很长时先落盘再定向读取，避免长输出反复进入上下文。
- **不做无信息量的确认。** 不问用户"要我继续吗"，也不反复检查同一状态。

### 长任务

- **后台执行，不轮询。** 耗时命令后台化，等完成通知，不 sleep 等待。

## 五、记录与展示

### 记录文件

`audit/token-ledger.json`，由 `scripts/lean.py` 维护：

```bash
python scripts/lean.py ledger <workspace> <step> --artifacts <文件...> --root <项目根>
python scripts/lean.py report <workspace>
python scripts/lean.py measure <文件或目录...>
```

判据、误差与不可测量项见 [Token 统计口径](../docs/TOKEN_ACCOUNTING.md)。**核心限制必须记住：脚本测的是文件产出物的 token，不是对话本身的 token。** 两者不能混为一谈，也不许互相顶替。

### 展示形式

每一轮给出结论之后，末尾附一行累计：

```text
📊 累计 token（产出物口径 · tiktoken:cl100k_base）：12,345
   对话本身 token：无法从本地读取 · 详见 docs/TOKEN_ACCOUNTING.md
```

要求：

- **必须标口径**。不标口径的数字没有意义。
- **必须标方法**。`tiktoken:cl100k_base` 是实测，`heuristic:...` 是估算，两者不能混着报。
- **不可测量的项要写"无法测量"**，不许用估值冒充实测，也不许省略这一行让它读起来像"已经全算进去了"。
- 数字用千分位，便于读。

## 六、标记有意的简化

凡是为了省 token 而**真的砍掉了一个有已知上限的东西**，用注释标出来，写清上限和升级路径：

```python
# ponytail: 只按扩展名筛文本，非文本附件直接跳过；需要处理 PDF/NetCDF 时再扩
```

```markdown
<!-- ponytail: 这里只写前 3 条最常见的错配；完整六类见 modules/evidence-integrity.md -->
```

**没有标记的简化等于埋雷。** 标记过的简化是一个有意为之的决策，将来能被找到、被升级。

## 七、检查

- [ ] 本轮产出里，有没有"以后可能用得上"而建的文件？有就删。
- [ ] 有没有重复读取同一文件、重复输出未变内容？
- [ ] 回复里有没有搬运文件正文？搬到文件里去。
- [ ] 有没有引入本可避免的新依赖？
- [ ] 本轮所有删减，是否都在"绝不可精简"清单之外？
- [ ] 有已知上限的简化，是否都加了 `ponytail:` 标记？
- [ ] 累计 token 那一行是否给出了口径与方法？
- [ ] 精简之后，用户要的东西是否**一件不少**？少了一件就退回。

## 八、与其他模块的关系

- 文献核验的完整性由 `modules/evidence-integrity.md` 保证，**精简模式不得触碰**。
- 图件数量与审查由 `modules/figures.md` 规定，**精简模式不得削减必出的图**。
- 交付前自查由 `assets/deai-checklist.md` 规定，**精简模式不得跳过第一层（证据完整性）**。
- 阶段闸门由 `docs/PHASE_GATES.md` 规定，**精简模式不得以"省事"为由降低阈值**。
- 引导话术由 `assets/plain-language-prompts.md` 规定。精简模式可以缩短回复，但不能把"下一步建议 + 可复制提示词"这两行省掉。
