# 论文写作总调度：一个入口，管住整条写作链

[返回首页](../README.md) · [五道关卡](#四层四道关卡流水线) · [四箱与事实锁](four-box-compression.md) · [阶段总控](phases.md)

**这是论文写作的总入口。** 你做一件事：把稿子交进来。剩下的由它按固定顺序推下去，每一步都留证据，每一步都对着同一个核心主旨。

**它解决一个具体的问题：** AI 写论文最常见的失败不是写不通，而是**写着写着跑偏了**——结果段开始罗列数据、结论段冒出无关内容、润色把数字改了、扩容时把定义丢了。这些都不是语法问题，是**流程没有护栏**。

所以这里不靠"提示词写得好一点"，靠**结构**：

| 失败模式 | 对应的护栏 |
|---|---|
| 结果段堆数字、不讲意义 | [靶心校验](bullseye-check.md) 直接驳回 |
| 结论段跑题 | [主题锚定](topic-anchoring.md) 直接驳回 |
| 润色偷偷改了数值 | [事实锁](four-box-compression.md) 硬校验，改了就驳回 |
| 正文里出现"我无法处理全部数据" | [内容过滤器](content-filter.md) 拦下 |
| 压缩后定义没了、数字还在 | 红锁**升级机制**把它拦住 |
| 结论没有文献支撑 | [引文布控](citation-placement.md) 在结论箱重点补 |
| 上下文爆了，稿子被压缩坏 | 四箱 + 只压缩副本，**导出永远读原始存档** |

---

## 一、四个阶段

```text
阶段0  导师引言风格蒸馏（可选，只在写引言时用）
        ↓  引言定稿 → 存入引言箱原始存档
阶段1  其余章节写作 + 五道关卡流水线
        ↓  全部通过 → 存入对应箱子的原始存档
阶段2  Token 监控 → 到阈值触发刹车 → 四箱事实锁压缩（只生成副本）
        ↓
阶段3  导出完整全文（直接拼四个箱子的原始存档）
```

**顺序不可颠倒。** 有以下强制关系：

1. **引言没定稿入库，压缩流程不碰引言箱。** 不允许边压缩边创作引言。
2. **五道关卡必须依次通过**，才允许入箱存档。
3. **导出永远读原始存档**，压缩副本只用于给模型推理时省上下文。

## 二、四箱是什么

| 箱 | 名称 | 信息密度 | 压缩上限 | 说明 |
|---|---|---|---|---|
| **A** | 引言箱 | 最低 | **6×** | 背景性内容多，可最高倍率抽取 |
| **B** | 数据箱 | 中等 | **3×** | 仪器、数据、方法 |
| **C** | 结果箱 | **最高** | **不压缩** | 一个句子都不能动 |
| **D** | 结论箱 | 次高 | **2×** | 轻度抽取 |

**为什么结果箱不压缩：** 结果箱里的每个数字、每个限定条件都直接支撑结论。压掉一个限定条件，结论的适用范围就变了。所以 C 箱的上限写死为 1.0×，脚本层面直接**拒绝**压缩它。

规则：压缩**只在箱内进行，不跨箱删句，不打乱段落顺序**。

细节与命令见 [四箱与事实锁](four-box-compression.md)。

## 三、三级事实锁

| 锁 | 内容 | 压缩时 |
|---|---|---|
| 🔴 **红锁** | 样本数量、观测时间、仪器名称、阈值、边界筛选条件、核心物理参数 | **100% 必须保留** |
| 🟡 **黄锁** | 次要限定条件、衍生参数 | 可舍弃，但**必须输出丢失清单** |
| 🟢 **绿锁** | 背景铺垫、过渡句、重复描述 | 可自由抽取 |

### 红锁升级：防止"数字留下、定义丢掉"

这是整套机制里最容易被忽略、也最致命的一条。

> "扰动幅度是 12.5 K，是安静基线的 3.1 倍。"

这里 **12.5 K 是红锁**。但"安静基线"的定义（前 10 天中位数）如果被压缩掉了，**12.5 K 这个数字就失去了意义**——读者不知道它相对于什么而言。

所以：**任何定义了红锁事实所涉及术语的句子，自动升级为临时红锁。**

脚本实现为 `locks.py` 的升级机制，并且在 `verify()` 里**强制执行**：如果定义句消失而术语仍在被使用，校验直接失败（`red_escalated_lost`）。不是提醒，是拦住。

## 四、五道关卡流水线

**顺序固定，不能跳。** 脚本层面没有提供 `--only`、`--skip` 这类开关——保证一条规则最省事的办法，是根本不提供绕过它的入口。

| # | 关卡 | 拦什么 | 模块 |
|---|---|---|---|
| 1 | **内容校验过滤器** | AI 自言自语、元叙述（"受限于上下文窗口，我无法处理"） | [content-filter](content-filter.md) |
| 2 | **主题锚定自检** | 每句话回头对照全文核心主旨，剔除跑题内容 | [topic-anchoring](topic-anchoring.md) |
| 3 | **写作靶心校验** | 射不中靶心、图文不匹配、数据平淡堆砌 | [bullseye-check](bullseye-check.md) |
| 4 | **去 AI 味专业润色** | 模板句、刻板句式；**且校验红锁没被改动** | [deai-writing](deai-writing.md) |
| 5 | **参考文献校验与引用布控** | 引文不匹配、格式错、结论段引文不足 | [citation-placement](citation-placement.md) |

### 一个反直觉但重要的设计

**第 4 关不交润色结果，就不能通过。** 也就是说：哪怕你认为不需要润色，也必须显式交回一个 `text_after`（内容和原文一样也算）。

**为什么：** 红锁校验必须有"改前"和"改后"两份文本才能做。如果不交，就等于这一关没跑过。**没跑过的关卡不能通过** —— 这是全流程的一贯原则。

### 每一关的判定

| 判定 | 含义 | 后续 |
|---|---|---|
| `pass` | 通过 | 进入下一关 |
| `flag` | 需要修改，但不阻断 | 记录问题，继续；**不得入箱存档** |
| `reject` | 驳回 | **停止该段落**，后续关卡不执行，返回重写 |

**前序驳回 → 后续关卡不执行。** 报告里会写明哪些关卡"未执行"，不允许假装它们跑过了。

### 每一关都重新验锁

凡是可能改动文字的关卡，边界处都会跑一次红锁校验（`locks.verify`）。任何一项红锁丢失、被改值、或凭空新增数字 → **该关卡直接驳回**。

实测例子（`tests/test_gates.py` 里钉住的）：

```text
改前：中层温度在扰动期间上升 12.5 K，持续 6 h。
改后：综上所述，中层温度在扰动期间上升 21 K，持续 6 h。
判定：reject —— polish changed protected facts: changed=[{'kind':'quantity','was':'12.5',...}]
```

**润色把 12.5 写成 21，被拦下了。** 这不是靠模型自觉，是脚本算出来的。

## 五、怎么用

### 输入文件

```json
{
  "core_thesis": "一句话核心主旨（写作前期录入，全程不变）",
  "core_questions": ["核心科学问题1", "核心科学问题2"],
  "domain_keywords": ["本项目的仪器名或核心参数名"],
  "citation_domain_keywords": ["结论段优先引用的方向关键词"],
  "references": [{"key": "R1", "title": "…", "doi": "10.…"}],
  "paragraphs": [
    {
      "id": "R1.1", "box": "results",
      "text": "待校验段落",
      "text_after": "润色后的段落（第 4 关必需）",
      "figures": [{"id": "2", "values": ["12.5", "8"]}],
      "citations": ["R1"]
    }
  ]
}
```

**`domain_keywords` 与 `citation_domain_keywords` 是项目级配置，不是写死的。** 本仓库保持通用；你自己的方向填自己的词。仪器名一旦声明为 domain keyword，就会被当作红锁保护。

**`figures[].values` 必须是你真实提供的图件数值。** 关卡只拿它做比对，**不会猜图里画了什么**。没提供就报 `cannot_check`，不会编。

### 命令

```bash
python scripts/gates.py run manuscript.json \
  --out review/gates.json --report review/gates.md

python scripts/gates.py report review/gates.json
```

输出：每个段落的五关判定 + 汇总（可入库 / 不可入库清单）。

### 通关之后

只有 `final_verdict == "passed"` 的段落才允许入箱：

```bash
python scripts/boxes.py init runs/my-paper
python scripts/boxes.py add runs/my-paper C --text "结果段落" --label "R3.1"
```

⚠️ **关卡没过的段落不要入箱。** 脚本不会替你判断"这篇是不是好文章"，它只保证：入箱的东西经过了哪些检查、哪些没过。

## 六、全局禁止行为（10 条）

这些是硬约束，`scripts/` 里能自动拦的已经拦了，剩下的是对模型的约束。

| # | 禁止 | 能否自动拦 |
|---|---|---|
| 1 | 不允许边压缩边创作引言；引言必须定稿存档后才生成压缩副本 | ✅ 部分（`compress` 不碰引言箱的原始存档） |
| 2 | 不允许生成抄袭文本；蒸馏只提取框架逻辑，禁止复制导师原文 | ❌ 需人工核对，见 [intro-distillation](intro-distillation.md) |
| 3 | 不允许跨箱删句、打乱段落顺序 | ✅ 自动（抽取式、按原序拼接） |
| 4 | 不允许把 AI 自身能力、限制、token、上下文写进正文 | ✅ 自动（第 1 关） |
| 5 | 不允许把压缩副本当最终输出源 | ✅ 自动（导出只读原始存档） |
| 6 | 主题锚定、靶心、润色、引文**严禁修改红锁参数、观测数据、核心结论** | ✅ 自动（每关边界验锁） |
| 7 | 润色禁止大幅改写，优先保留作者原表达 | ⚠️ 部分（检测模板句与节奏，幅度靠人看） |
| 8 | 补充文献不能编造；结论段新增引用必须贴合上下文 | ✅ 部分（只推荐清单里已有的文献，未知 key 直接驳回） |
| 9 | 图文校验不能凭空臆测图表内容 | ✅ 自动（无图件数据则报 `cannot_check`） |
| 10 | 结果、结论章节任何句子不能脱离全文核心主旨 | ✅ 部分（锚定关卡驳回无关联段落） |

**"无法自动拦"的三项已如实标注**，不要以为跑完脚本就万事大吉。

## 七、诚实的边界

- **锚定与靶心的判定是启发式的。** 脚本用术语重合度做初筛，真正"这句话有没有服务主旨"的语义判断仍在模型/人身上。报告里明确写着 `heuristic_term_overlap`。
- **红锁识别是模式匹配。** 能覆盖"数字 + 单位、n=、不等号阈值、日期时间"，以及你声明的仪器名。**不认识的写法会漏**——所以 `domain_keywords` 一定要填全。
- **它不判断科学正确性。** 它保证的是流程完整性与事实不被篡改，不是结论对不对。
- **它不给录用概率。** 见 [审稿人评审](reviewer-panel.md)。
