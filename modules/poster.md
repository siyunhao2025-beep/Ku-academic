# 海报制作：先问三件事，再动手

[返回首页](../README.md) · [图的规则](figures.md) · [阶段总控](phases.md) · [讲解版 Word](explainer-docx.md)

**流程与做 PPT 类似，但有一处硬差别：动手之前必须先问清三件事。**

先打个比方。

**像去打印店做易拉宝。** 店员一定先问你三句：**做多大、写中文还是英文、要电子图还是源文件。** 这三句不问清楚，做出来就是废的——A0 的版排到 A4 上看不清，英文稿印成中文没人读，只要图片的话给你源文件你也不会改。

**所以本模块的设计是：三件事没答完，一张图都不生成。**

---

## 一、必答的三个问题

### 问题 1 · 海报尺寸

| ID | 尺寸 | 用途 |
|---|---|---|
| `a0` | A0（841 × 1189 mm） | 标准学术海报，会场最常用 |
| `a1` | A1（594 × 841 mm） | 场地较小或内容较少 |
| `a2` | A2（420 × 594 mm） | 组会、走廊展示 |
| `a3` | A3（297 × 420 mm） | 打印店随手出 |
| `a4` | A4（210 × 297 mm） | 贴墙小样、打印预检，**不是正式海报尺寸** |
| `conf-90x120` | 900 × 1200 mm | 国内学术会议常见**竖版** |
| `conf-120x90` | 1200 × 900 mm | 国内学术会议常见**横版** |
| `screen-16x9` | 屏幕 16:9 | 投屏、线上展示、社交媒体 |

方向默认 `auto`——**按尺寸名自身的横竖来**，不会偷偷旋转。要强制横竖再用 `--orientation portrait|landscape`。

### 问题 2 · 海报语言

`zh`（中文）或 `en`（English）。**只影响文案骨架与默认字体栈，不影响排版逻辑。**

### 问题 3 · 输出形式

| ID | 输出 | 说明 |
|---|---|---|
| `image` | 直接输出图片 | **SVG，1 单位 = 1 mm**，物理尺寸写在文件里，可直接送印。矢量，放大不糊 |
| `ppt` | 输出为 PPT | 单页 `.pptx`，尺寸与海报一致，便于你继续用 PowerPoint 改 |

**为什么图片给的是 SVG 而不是 PNG：** SVG 是矢量，印刷质量更好，且物理尺寸是**真实**写进文件的（`width="841.0mm"`）。想转 PNG 用任何渲染器都行，但本模块**不假装**自己能光栅化——那需要一个渲染器或一个字体引擎，属于依赖，不在本模块范围内。这件事在下面第五节说清楚。

## 二、怎么用

```bash
# 1) 打印三组选项（用来问用户，不要自己编选项）
python scripts/poster.py choices

# 2) 三件事答完才建规格；缺任何一项都会报错退出
python scripts/poster.py plan \
  --size a0 --lang zh --output image \
  --title "你的海报标题" \
  --palette research \
  --out poster/spec.json

# 3) 渲染
python scripts/poster.py render poster/spec.json --out poster/poster.svg     # 图片
python scripts/poster.py render poster/spec.json --out poster/poster.pptx    # PPT
```

### 缺选项时的行为（这是本模块的核心约束）

```text
$ python scripts/poster.py plan --size a0 --out spec.json
three choices are required before any poster work starts; still missing:
海报语言 (--lang); 输出形式 (--output)
Run `python scripts/poster.py choices` to see the canonical option list, then ask
the user to pick. Do not assume a default.
```

**退出码 2，不写任何文件。** 只给了尺寸、只给了语言、或者一项都没给，行为完全一致：报错并列出还缺哪几项。

**不许替用户默认。** 脚本层面已经堵死了：三个参数任一为空就拒绝执行。

## 三、版式引擎怎么排

规格建好之后，`render` 会：

1. **按面积缩放字号。** 以 A0 为基准（缩放系数 1.0），范围夹在 0.35–1.2。A0 上标题约 26 mm、正文约 7.2 mm。
2. **自动定栏数。** 竖版窄高用 2 栏，横版宽扁用 3 栏。
3. **贪心填栏。** 每个内容块放进当前最短的那一栏，块高按中英文混排的估算行数算（CJK 按 1 em、拉丁按 0.55 em 估宽）。
4. **页眉与页脚固定。** 标题（含作者/单位）占顶部通栏，页脚（致谢、数据可得性）占底部通栏。
5. **产出指标并回写进规格**：栏数、边距、字号、内容底部高度、**填充率**、**重叠检测结果**、**残留占位符**。

### 两个自我保护

| 检查 | 行为 |
|---|---|
| **重叠检测** | 任意两个块发生重叠 → 打印 `overlaps` 并**退出码 2**。布局有问题就不许当成功 |
| **占位符检测** | 骨架里还留着 `⟨在此填写⟩` → 打印 WARNING 并说明"这是版式骨架，不是成品海报"。加 `--strict` 时直接退出码 2 |

填充率低于 70% 时会提示：真实海报每一节通常承载更多证据。**骨架天生是稀疏的**，这个提示是让你别把骨架当成品交出去。

## 四、四类色板与配色逻辑

| ID | 用途 |
|---|---|
| `research` | 默认。深紫页眉 + 白底，学术会议通用 |
| `vivid` | 高饱和，适合线上展示与社交媒体 |
| `minimal` | 浅灰页眉，适合打印成本敏感或黑白印刷 |

**配色逻辑（写进规格的 `colour_rule` 字段）：**

1. **颜色不单独承载信息。** 任何区分同时用第二通道标注——小标题文字、分隔线、字重、圆点标记。色盲读者与黑白打印都必须能读懂。
2. **页眉深、正文浅。** 对比度优先于好看。
3. **正文纯深灰（近黑），不用纯黑也不用彩色。** 大量文字用彩色会降低可读性。
4. **强调色只用于圆点和个别框线**，不用于大块填充。

## 五、已知边界（不要假装没有）

| 边界 | 说明 |
|---|---|
| **不做 PNG 光栅化** | `image` 输出是 SVG。要 PNG/PDF 请用你自己的渲染器（浏览器打印、Inkscape、Illustrator 均可）。本模块不引入渲染依赖 |
| **不做图片嵌入** | 海报里的"图 1"是一个**位置块**，不是把你的图放进去。真实做法：在 SVG 里替换该块，或用 PPT 输出后自行插入。插入图片需要处理二进制与排版，超出本模块范围 |
| **行高是估算** | 块高按字符宽度估算，不测量真实字体度量。极端长词或大量公式可能估偏，这时用重叠检测兜底 |
| **SVG 文本不自动换行** | SVG 没有自动换行，本模块**自己按字符算断行**再逐行输出 `<text>`。因此换行位置是估算的，不是排版引擎给的 |
| **字体依赖系统** | 字体栈含 `Microsoft YaHei`、`PingFang SC`、`Noto Sans CJK SC`。送印前**必须在目标机器或打印店预览一次**，确认中文字体没被替换成方框 |
| **不做出血与裁切线** | 正式印刷如需 3 mm 出血，请自行在 PDF 阶段处理 |

**送印前必做一件事：把 SVG 在真实尺寸下打印一页 A4 小样，量一下正文字号是否还能看清。** 屏幕上看和纸上读是两件事。

## 六、检查清单

- [ ] **三个问题都已由用户明确选择**，没有用默认值代替。
- [ ] 物理尺寸与会议要求一致（有的会议规定必须是 A0 竖版）。
- [ ] 语言与听众一致。
- [ ] 输出形式满足用途：要送印选图片，要现场改选 PPT。
- [ ] `overlaps` 为 `none`。
- [ ] 占位符已全部替换，没有残留 `⟨在此填写⟩`。
- [ ] 内容填充率合理（低于 70% 时确认是不是内容太少）。
- [ ] 每个区分都用了第二通道，不只靠颜色。
- [ ] 送印前用真实字体预览过一次。
- [ ] 数字与正文/论文一致——海报上的数**最容易在赶工时写错**。

## 七、与 PPT 流程的关系

海报流程与 PPT 流程共用同一套「先理解需求 → 定设计系统 → 逐块完成 → 验收交付」骨架，差别在于：

| | PPT | 海报 |
|---|---|---|
| 开头 | 场景路由（学术/商业/培训……） | **三个必答问题** |
| 版式 | 一页一个论点，逐页推进 | **单页整体版式，栏数自动** |
| 色彩 | 按场景选风格家族 | 三套色板，打印优先 |
| 输出 | 飞书 Slides / PPTX | SVG 或 PPTX |

PPT 部分的完整规则见 `skills/ppt/SKILL.md`。**注意该技能有缺失依赖**（缺 5 个 Python 工具与 2 个 XML 文件，且需要 `lark-cli`），详见 [skills/ppt/MISSING_DEPENDENCIES.md](../skills/ppt/MISSING_DEPENDENCIES.md)。
