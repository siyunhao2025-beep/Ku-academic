# 变更管理：上游一改，下游不许静默过期

[返回首页](../README.md) · [阶段总控](phases.md) · [图件护栏](figures.md) · [引用真实性](evidence-integrity.md)

科研不是一条直线走到黑。检索词会改、设计参数会调、结果会重跑、稿件会返修。**真正危险的不是"改"，而是改了上游、下游还停在旧版本，却没人知道。** 一张用旧结果画的图、一段引用了已被推翻证据的讨论、一个数字三处对不上——大多不是能力问题，是变更没有传播。

先打个比方。

**像改建筑图纸。** 你把承重墙的位置挪了 30 厘米，不能只改平面图：结构图、水电图、材料清单、施工顺序全都要跟着改，而且要知道**具体哪几张图**受影响、哪几张不用动。只凭"我记得差不多都改了"就开工，楼会塌。科研产物之间也有这样的承重墙——`scope.json`、`design.json`、`analysis/results/` 就是。

本模块给三件东西：**变更分级**（判断这次改动有多重）、**影响分析脚本**（自动算出波及范围与回退站点）、**回退 SOP**（怎么干净地重做，而不是东补一块西补一块）。

---

## 一、先分级：这次改动有多重

动手改之前，先判断它属于哪一级。级别决定回退到哪一站，**不要用"改个错别字"的流程对待"改实验参数"，也不要为一个标点回退整个项目。**

| 级别 | 典型改动 | 是否改变科学含义 | 处理 |
|---|---|---|---|
| **L0 排版/文字** | 错别字、语法、参考文献格式、图注措辞润色、字号 | 否 | 只改该处，不回退；改完过一遍对应写作关卡即可 |
| **L1 表述/范围** | 收窄论断范围、把"导致"改成"与……一致"、调整结论强度、补限定条件 | 措辞层面 | 受影响段落重跑五道写作关卡；**摘要、结论、图注、claim-map 里同一论断必须同步** |
| **L2 结果/分析** | 重跑计算、改数据筛选/质控、换分箱、补误差、改绘图 | 是（数字可能变） | **回退到 P4**：结果→稳健性→图→论点表→正文结果/讨论→结论，逐站重做 |
| **L3 设计/方法** | 改参数、改匹配方法、增删替代设置、改混淆处置、换数据源 | 是（方法链变） | **回退到 P3**：从设计改起，P4/P5/P6 全部重走 |
| **L4 问题/证据基础** | 改主问题或子问题、改检索式、纳入/排除关键文献、缺口结论变化 | 是（根基变） | **回退到 P1 或 P2**：重新检索/补证据，之后全部重走 |

**判断不了是几级，就按更重的一级处理。** 宁可多重做一段，不可让过期产物混进终稿。

## 二、影响分析：让脚本告诉你波及谁

不要靠脑子记"这个改动会影响啥"。仓库内置了七阶段标准产物依赖图，用脚本正向传播：

```bash
# 看整张依赖图，理解谁是谁的上游
python scripts/impact.py graph

# 改之前/之后，指定你动了哪个产物，算出后果
python scripts/impact.py analyze <workspace> --changed design.json

# 也可以一次给多个变更；不确定路径时，脚本会列出无法识别的文件
python scripts/impact.py analyze <workspace> --changed evidence.json analysis/results/x.csv

# 放进闸门/自查：只要有下游被污染就非零退出
python scripts/impact.py analyze <workspace> --changed design.json --strict
```

报告给出四件事：

1. **根因变更**：你动的文件映射到哪个标准产物；
2. **受影响下游**：按 P1–P6 分组，每个产物写明**重做动作**（重跑 / 重画 / 重写 / 重核）和**传导链**（它为什么受影响，例如 `design → run_log → results → figures`）；
3. **建议回退阶段**：受影响节点中最早的一站；
4. **可安全保留**：本次变更不直接波及的产物（重跑后仍建议抽查，但不必重做）。

报告同时写入 `audit/impact-report.json`，留痕可追溯。

### 与 checkpoint 联动：自动发现"静默变更"

如果你在每个阶段用 `research.py checkpoint` 登记过产物哈希，影响分析可以**不指定 `--changed`**，自动比对出哪些登记文件已经变了：

```bash
python scripts/research.py checkpoint <workspace> P4 \
    --inputs design.json --outputs analysis/run-log.json analysis/results/r.csv
# ... 之后某个文件被改动 ...
python scripts/impact.py analyze <workspace>     # 自动从哈希漂移推断根因
```

`research.py` 的 check 负责发现"哪个文件变了/缺了"，并沿 checkpoint 登记的输入输出关系做初步失效传播；`impact.py` 在此基础上用标准依赖图补全**具体产物、动作、回退站点**。两者分工：一个发现漂移，一个解释后果。

> 边界：依赖图覆盖的是**产物级**依赖（文件 A 是文件 B 的上游）。一句话的改动是否动摇了整段论证，属于**语义影响**，脚本穷尽不了——报告每次都会显式提醒这一点，不假装算尽了一切。拿不准语义波及范围时，按更重一级处理并请人复核。

## 三、回退 SOP：干净重做的五步

确认级别、跑完影响分析后，按下面五步走，不要东补一块西补一块。

1. **冻结现场**。不要先删旧产物。把当前版本留着（git 提交一次，或复制到 `runs/` 下带日期的目录），便于对照"改了什么、为什么"。
2. **跑影响分析，确认回退站点**。`impact.py analyze --changed <文件>`，对照第一节分级表确认回退阶段一致；不一致就以**更早**的站点为准。
3. **从回退站点正向重做**，一站一清：
   - 重跑计算 → 新结果进 `analysis/results/`，**禁止手改数字**，失败也如实进运行日志；
   - 用新结果重画图（`figures.py check` 重过，人眼重审，`visual_review` 重新署名）；
   - 重建 `claim-map.json`，受影响论断重新链接证据/图/章节；
   - 改写受影响正文段落，过五道写作关卡；
   - 同步摘要、结论、图注里的同一论断（L1 起就必须做）；
   - 受影响引用重跑两道核验（`citation-final.json`）。
4. **重新登记 checkpoint**。重做完成后对各阶段重新 `checkpoint`，让哈希基线更新到新版本，否则下次 check 会一直报 stale。
5. **重过对应闸门**。回退到哪一站，就从那一站的 `progress.py gate` 重新往后过，一路过到 P6；**闸门不因为"只是小改"而跳过**。

### 阈值、纳入标准、参数变更的额外纪律

科学上最容易出问题的是"悄悄改标准"：检索纳入阈值从 8 分改成 6 分、显著性门槛从 0.05 改成 0.1、最小样本量下调。这类改动**必须**：

- 在 `audit/review.md`（或 `analysis/run-log.json`）里记录：**旧值 → 新值、改动理由、是谁/什么证据触发的**；
- 用影响分析评估：阈值一变，之前被纳入/排除的条目可能翻转，**证据矩阵、缺口、结果要重算，不能只改往后的部分**；
- 若改动是"看到结果后为了得到想要的结论而改标准"，按 p-hacking 处理——要么回到预登记标准，要么把改动明确写成事后调整并在文中声明。

---

## 四、三条硬禁令

1. **禁止手改结果文件里的数字**。数字只能由脚本从数据重新生成；发现结果有误，回去改数据/代码重跑，不直接编辑结果。
2. **禁止改了上游不传播**。任何 L2 及以上变更，必须留下 `impact-report.json` 和重做记录；"我觉得下游没受影响"不能作为不重做的理由。
3. **禁止静默改阈值/标准**。一切纳入标准、显著性门槛、参数取值的变更都要留痕并评估翻转影响。

---

## 五、与其他模块的关系

- 影响分析是横切模块，在 **P3–P6 任何一次返工/返修**时触发；返修的逐条编号与五格回应流程见 `modules/phases.md` 的 P6 与 `docs/USE_CASES.md` 第 14 节。
- 回退后重做的图走 `modules/figures.md` 与 `figures.py`；引用重核走 `modules/evidence-integrity.md`。
- 回退与重做的"能不能进入下一阶段"仍由 `scripts/progress.py gate` 依据 `docs/PHASE_GATES.md` 判定，影响分析只回答"要重做什么"，不替代闸门。
- 所有变更与影响报告落在 `audit/`，与运行日志、引用溯源一起构成可审计轨迹。
