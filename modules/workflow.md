# 总控：两条研究路线，六个阶段，依赖变化时回溯

首先读取用户已有文件和 project.json，不重复询问已知信息。明确研究问题、资料覆盖、体裁、领域包、工具状态和输出目标。建立 claim ledger：主张、证据类别、源文件/DOI、页段/图表/运行位置、适用条件、反例、引用状态。

**阶段契约见 `modules/phases.md`：六阶段 P1–P6，每阶段的输入、执行步骤、产出物、检查清单。** 下面两条路线是这六阶段在两类任务上的具体展开。

**精简模式见 `modules/lean-mode.md`：默认 `full` 档。** 走最懒但真能用的路径，复用项目已有的产物，绝不砍掉数字、引用核验、证据强度和图件审查。为省 token 砍掉的东西要加 `ponytail:` 标记。

## 六个阶段（所有任务共用）

P1 选题与论文调研 → P2 文献综述 → P3 实验设计 → P4 计算与结果 → P5 图表与论文写作 → P6 结论与投稿返修。

上一阶段的产出物是下一阶段的输入。缺输入不要开工，先补上一步。阶段闸门、阈值与产物结构见 `docs/PHASE_GATES.md`。

## 原创研究

范围与初始问题 → 文献/方法证据 → 设计与数据审计 → 实际计算 → 对照/稳健性检查 → 结果表和图件 → 方法/结果 → 讨论/引言修订 → 摘要/结论 → 科学与引用审查 → 语言修订。
框架可以早建，但结果和机制不能提前写定。上游参数、基线或样本变化时，重审所有依赖图件、段落和摘要。用 checkpoint/check 记录与检查，而不是声称已实现任意分析代码的自动重跑。

## 综述

明确叙述性/范围/系统综述 → 检索方案 → 多源检索与筛选 → 全文证据矩阵 → 比较方法、结论与条件 → 主题框架 → 分节综合 → 引用/图表核查 → 修订。
没有相应过程记录，不把一般文献整理标成系统综述。框架按问题组织，而不是逐篇摘要排队。新论文先判定对综合结论的贡献，不能为追求新颖而替换基础文献。

## 每个任务都要出的三类图

科研线路图（从数据到结论的路径）、原理示意图（机制或方法）、数据图（真实结果）。规则与检查清单见 `modules/figures.md`。示意图必须标为概念示意；图件必须经人眼审查，不能凭文件存在报告通过。

## 文章写完之后的三件交付

| 交付 | 模块 | 关键约束 |
|---|---|---|
| 审稿人评审 | `modules/reviewer-panel.md` | **3–5 位审稿人独立打分，不许取平均**；没提科学问题判为覆盖不足；不给录用概率 |
| 讲解版 Word | `modules/explainer-docx.md` | 七节固定结构；数字与论文逐项一致；只翻译不发明 |
| 海报 | `modules/poster.md` | **先问尺寸 / 语言 / 输出形式，答完才动手**；重叠即判失败 |

## 写作运行时的总调度

`modules/paper-orchestrator.md` 是论文写作的总入口，管四个阶段：导师引言蒸馏 → 其余章节写作 + 五道关卡 → Token 刹车与四箱压缩 → 导出完整全文。

**五道关卡顺序固定、不可跳**：内容过滤器 → 主题锚定 → 靶心校验 → 去 AI 味润色 → 引文校验与布控。前序驳回则后续不执行，报告里写明哪些关卡未执行。

**四箱与事实锁**：A 引言箱 6×、B 数据箱 3×、C 结果箱**不压缩**、D 结论箱 2×。红锁（样本量、观测时间、仪器名、阈值、边界条件、核心参数）100% 保留，凡是定义红锁所涉及术语的句子自动升级为红锁。压缩只生成临时副本，**导出永远读原始存档**。

脚本：`scripts/gates.py`（五关）、`scripts/boxes.py`（四箱与刹车）、`scripts/locks.py`（事实锁校验）。

幻灯片走第三方技能 `skills/ppt/SKILL.md`，**使用前先读 `skills/ppt/MISSING_DEPENDENCIES.md`**（缺 5 个 Python 工具与 2 个 XML 文件，且需要 `lark-cli`）。

## 每个引用都要过两道检

身份（是否存在、出处是否准确）与支持（是否真的支持这句话）分开判定，判定值与阻断项见 `modules/evidence-integrity.md`。无法核实的显式标 `待确认`，且不得进入论证链。

## 阶段产物

scope.json：研究问题、体裁、时间范围、资料来源、已知限制。
glossary.md：术语与同义词、坐标与地方时命名约定。
evidence.json：已读证据和可定位的来源，含 citation_verdict 与 support_status。
claim-map.json：论点—证据—结果文件—图表—章节的对应关系。
analysis/run-log.json：数据/代码哈希、配置、版本、时间、命令、输出、失败。
methods-map.json：每个操作性 Methods 陈述对应的代码与运行记录。
figures/manifest.json：源数据、处理、坐标、单位、不确定度定义、配色与冗余编码、输出。
manuscript/changes.json：有证据支持的修订。
audit/citation-provenance.json：引用身份与支持判定、blockers、待确认清单。
audit/deai-selfcheck.md：交付前自查记录。
audit/token-ledger.json：产出物 token 台账，每步含口径与方法标签；对话 token 记 not_measurable_from_here。
review/panel.json：3–5 位审稿人的七维评分、逐条意见、结论与分歧统计。
poster/spec.json：海报尺寸、语言、输出形式、版式指标与重叠检测结果。
audit/review.md：真正会影响解释或复现的待处理问题。

继续执行独立、可逆的步骤；信息不足时输出可用成果和明确的阻塞项。不用“全自动”掩盖未执行步骤。投稿、付费、对外共享、访问受限资料都须遵循用户授权和宿主权限。
