# 总控：两条研究路线，依赖变化时回溯

首先读取用户已有文件和 project.json，不重复询问已知信息。明确研究问题、资料覆盖、体裁、领域包、工具状态和输出目标。建立 claim ledger：主张、证据类别、源文件/DOI、页段/图表/运行位置、适用条件、反例、引用状态。

## 原创研究
范围与初始问题 → 文献/方法证据 → 设计与数据审计 → 实际计算 → 对照/稳健性检查 → 结果表和图件 → 方法/结果 → 讨论/引言修订 → 摘要/结论 → 科学与引用审查 → 语言修订。
框架可以早建，但结果和机制不能提前写定。上游参数、基线或样本变化时，重审所有依赖图件、段落和摘要。用 checkpoint/check 记录与检查，而不是声称已实现任意分析代码的自动重跑。

## 综述
明确叙述性/范围/系统综述 → 检索方案 → 多源检索与筛选 → 全文证据矩阵 → 比较方法、结论与条件 → 主题框架 → 分节综合 → 引用/图表核查 → 修订。
没有相应过程记录，不把一般文献整理标成系统综述。框架按问题组织，而不是逐篇摘要排队。新论文先判定对综合结论的贡献，不能为追求新颖而替换基础文献。

## 阶段产物
scope.json：研究问题、体裁、时间范围、资料来源、已知限制。
evidence.json：已读证据和可定位的来源。
claim-map.json：论点—证据—结果文件—图表—章节的对应关系。
analysis/run-log.json：数据/代码哈希、配置、版本、时间、命令、输出、失败。
methods-map.json：每个操作性 Methods 陈述对应的代码与运行记录。
figures/manifest.json：源数据、处理、坐标、单位、不确定度定义、输出。
manuscript/changes.json：有证据支持的修订。
audit/review.md：真正会影响解释或复现的待处理问题。

继续执行独立、可逆的步骤；信息不足时输出可用成果和明确的阻塞项。不用“全自动”掩盖未执行步骤。投稿、付费、对外共享、访问受限资料都须遵循用户授权和宿主权限。
