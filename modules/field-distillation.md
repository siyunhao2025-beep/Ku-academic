# 从领域资料提炼可执行知识

目标是“下一次遇到同类研究问题时知道何时采用何种方法”，不是论文摘要合集。

先为全文、仪器文档、代码建立目录、版本和来源清单。完整方法、公式或适用条件即使只出现在一处，也不能因没有重复出现而丢弃。文献结论、领域可复用规则、本项目发现分开存储。

每张能力卡包含：ID；触发任务；输入与单位；完整操作；参数由何处确定；输出；可执行验证；适用范围；反例/冲突；原文定位；证据等级；相邻方法的区别。规则状态使用 candidate / usable_within_scope / reference_only / unresolved。单次事件结果不升级为领域定律。

## 方法谱系：解释方法为什么演化

当用户问“方法怎么演化、为什么后来方法替代前一代、哪个方法适合我的条件、真正缺口在哪里”时，在能力卡之外建立项目级 `lineage.json`。普通文献整理或单篇精读不强制生成它；不要为凑产物给每个项目画谱系。

先用既有 `search-log.json` 与 `evidence.json` 做主题地图，再从争议或关键方法中选择锚点。锚点不能只凭被引数决定，也要记录它为何与研究问题直接相关、是否代表概念标准/常用基线/当前前沿，以及它的别名、版本和规范引用。

每个方法节点至少记录：

- `source_ids`：回链到 `evidence.json` 的证据 ID；
- `assumptions`：显式和隐含前提；
- `mechanism`：方法用什么设计选择产生作用；
- `price`：新增代价、数据要求、计算成本或失败模式；
- `wins_when` / `fails_when`：适用条件与失效条件；
- `limitations`：分别标记 author_stated / later_reported / inferred，推导项不得冒充作者结论。

每条前代 → 后继转移至少回答五件事：**假设变化、实现机制、新增代价、适用条件、失效条件**。同时记录 `evidence_ids`、发现渠道和结论状态 `claimed / demonstrated / inferred`；一张基准表上的优势不能替代机制解释，不同数据、预算、调参或人群下的比较不得写成公平胜出。

后继检索至少相互校验三条渠道：

1. **引用链**：前向引用、后向引用、作为 baseline 的工作；
2. **局限反推**：把节点的具体局限改写成不含方法名的修复查询；
3. **问题框架**：按任务的不同研究框架、近年窗口和相关领域术语检索。

每条查询继续使用既有检索日志，记录来源、时间、命中、去重、纳入、截断和失败。**检索失败不等于零命中**；某一渠道没有产出时，应说明是执行失败、覆盖不足还是实际零命中，不能据此断言不存在后继工作。引用链也可能复制一个团队的视角，须检查作者组与来源渠道是否过度集中。

只有通过引用身份/支持双检的证据才能进入谱系论证。书目信息可用 `metadata_only`，方法存在性至少要读摘要；有关假设、机制、定量收益或失效条件的节点与转移必须有 `full_text`（或 `project_result`）及页/图/表定位。`PARTIALLY_SUPPORTS` 要同步收窄表述，`CONTRADICTS`、`DOES_NOT_SUPPORT`、`CANNOT_VERIFY` 不得被画成已成立的演进边。

跨领域迁移先把方法改写成不含领域名的抽象问题，再逐项核对目标领域是否满足其假设、需要什么适配、可能在哪里失效，以及是否已有人在目标领域采用。只能写“在已记录的查询与来源中未找到”，不得写成“没人做过”。最终把可迁移机制写回能力卡时，仍须保留条件、代价、反例和来源；谱系图本身不是新颖性证明。

机制资料逐条区分 observed / statistical association / proposed explanation。存在不一致时比较数据源/仪器、时间与空间/分组条件、阶段、对照基线、样本与分析口径（具体条件维度以领域包为准），不机械多数表决。只抽取来源足以支持的结论；推导注明它是当前分析的推导。

检验使用未参与提炼的材料。测试至少覆盖：换数据源/坐标、换对照基线、缺失关键解释变量、随机噪声与相关样本、资料矛盾、摘要不足、引用错配。对比通用提示词、通用母 Skill、领域包三个条件，记录真实输出差异，不凭感觉宣称性能提升。

本包的 domain.json 是接口和审查清单，不是已经从用户论文蒸馏完成的知识库。新增领域通过独立目录和相同接口替换；不写入固定个人画像或固定事件结果。中性空模板见 `domains/example-domain/`，一份填好的示范（空间物理，仅作格式教具、非默认值）见 `domains/sample-space-physics/`。
