# 图：一张路线图、一张原理图、一批数据图

[返回首页](../README.md) · [阶段总控](phases.md) · [同类对比来源](../docs/PEER_COMPARISON.md)

**每个研究任务默认产三张图，一张都不能省：**

1. **科研线路图（roadmap）** —— 你从数据走到结论的路径。给读者看"你干了什么"。
2. **原理示意图（schematic）** —— 你研究的机制或方法长什么样。给读者看"这件事为什么这样发生"。
3. **数据图（data figure）** —— 真实结果的定量呈现。给读者看"数字是什么"。

先打个比方。

**像给朋友指路。** 线路图是"导航路线"——从家到餐厅，几个路口，左转右转。原理图是"餐厅长什么样"——进门是前台，左边是厨房，你的桌子在窗边。数据图是"菜单上的价格"——具体多少钱。

三张图各回答一个问题，谁也不能替代谁。**把价格画进路线图里，就是把两件事混在一起。**

## 一、科研线路图（roadmap）

### 什么时候画

P1 画出草图（回答"打算怎么做"），P4 定稿（回答"实际怎么做的"）。**两版要分开存**，投稿前对照检查，计划与实际的差异要么补做，要么说明。

### 图里必须有的东西

| 要素 | 说明 |
|---|---|
| 数据来源 | 仪器、数据集、时间跨度、空间覆盖 |
| 处理链 | 每一步筛选、质控、坐标转换、分箱 |
| 分析 | 方法名与实际参数 |
| 输出 | 结果量、图件、统计 |
| 结论 | 从哪个结果得到哪个结论 |
| 分叉 | 试过的替代设置，以及为什么保留/放弃 |

### 硬规则

- **每个形状都必须代表一个具名事物。** 不允许出现"抽象的彩色方块"充当装饰或占位。一个方块如果没法命名，就删掉。
- **方向必须唯一。** 图上流动的方向要一致（左→右 或 上→下），不要两种混用。
- **形状词汇固定**：过程 = 矩形，数据/存储 = 圆柱，判断 = 菱形，外部输入 = 圆角矩形。同一篇论文里不能换。
- **层级要一致。** 同一张图里，不能一边画到"载入 CSV"这种粒度，另一边只写"完成分析"这种粒度。
- **主路径加粗，替代路径虚线。** 读者一眼就知道主干在哪。
- **文字最小 8 pt（印刷尺寸下）**，白底，浅色/灰度打印仍能读。
- **写清楚哪部分是你做的、哪部分用的是别人的数据或方法**。用不同边框样式区分，不要靠颜色。

### 检查清单

- [ ] 每个形状都能说出它的名字和含义。
- [ ] 主线路径唯一且连续，没有断头路。
- [ ] 计划版与实际版的差异已比对过，差异有解释。
- [ ] 替代设置画在图上，不是只写在正文里。
- [ ] 缩小到单栏宽度后最小字号仍 ≥8 pt。
- [ ] 转灰度后仍能分辨层次（不依赖颜色区分）。
- [ ] 图注能独立看懂：数据来源、处理、方法、输出都标了。

## 二、原理示意图（schematic）

### 先选原型

按内容选一种，不要混着画。

| 原型 | 什么时候用 | 典型位置 |
|---|---|---|
| 架构图 | 展示系统/模型的分层结构 | Methods 或引言末 |
| 流程图 | 展示机制的时间顺序 | Discussion |
| 组件图 | 展示一个量的构成与来源 | Methods |
| 概念图 | 展示抽象概念之间的关系 | Introduction |
| 对比图 | 并排展示两种条件/两种机制 | Discussion |
| 分类图 | 展示类型划分 | Introduction 或 Discussion |
| 部署/观测构型图 | 展示仪器几何、观测几何 | Methods |

### 机制图必须区分的层级

如果图里画的是机制（"热量怎么传""风怎么吹"），**必须用视觉方式区分证据等级**：

| 层级 | 视觉表达 |
|---|---|
| 已观测到 | 实线箭头 + 实心图形 |
| 推断 | 虚线箭头 + 空心图形 |
| 假说 | 点线箭头 + 问号标记 |

三层不区分，就是拿推断冒充观测。这是机制图最常见的严重问题。

### 硬规则

- **概念图必须标为"概念示意"**，在图注里明说。绝不能让人误以为是观测结果或数据图。
- **不要硬塞 AI 生成图。** 有些论文不需要示意图，图注里说明为什么不需要比硬凑一张好。
- **不允许用颜色块代替命名。** 每个形状都要有文字标签。
- **跨图一致性**：同一篇论文里的所有示意图，配色语义必须锁定（同一个颜色永远指同一件事）；字体、线宽、节点形状统一；组件命名一致；同一抽象层级的图复杂度相近。
- **矢量格式输出**，便于期刊排版。
- **最多迭代 3 轮**。第 3 轮还讲不清楚，说明你的机制本身没想清楚，回去改文字，不要继续调图。

### 检查清单

- [ ] 选定的原型与内容匹配。
- [ ] 机制层级（观测/推断/假说）用视觉方式区分了。
- [ ] 图注写了"概念示意"。
- [ ] 每个形状都有具名标签，没有纯装饰元素。
- [ ] 与同篇其他图的配色语义、字体、线宽一致。
- [ ] 数据墨水比合理：没有为了好看而加的无信息元素。
- [ ] 矢量输出，印刷尺寸下文字 ≥8 pt。

## 三、数据图（data figure）

### 数据从哪来

只从真实结果文件出图。**不准用生成式工具造数据图。** 手工编辑过数字的结果文件不能作为绘图输入。

### 必须留档的东西

源数据、绘图脚本、参数、坐标轴与色条范围、掩膜与缺测处理、图注文本、PNG 与矢量两种输出。

### 颜色：不要只用颜色传信息

这是本模块最重要的一条。**永远不要把信息只编码在色相里。** 色盲读者、灰度打印、屏幕偏色都会把它毁掉。

颜色必须配一个第二通道：

- 标记形状（圆/方/三角）
- 线型（实线/虚线/点线）
- 填充纹理（斜线/点阵）
- 直接标注（把标签贴在线上，而不是只放图例）

### 配色选择

| 用途 | 推荐 |
|---|---|
| 分类（≤8 类） | 优先无障碍色板：`okabe-ito`（8 色，首选）、`tol-bright`（7 色）、`tol-muted` / `tol-light`（9 色）、`tol-high-contrast`（3 色，灰度安全） |
| 顺序 / 发散 | `viridis`、`cividis`、`magma` |
| 不要用 | 彩虹色 `jet` / `rainbow`（感知不均匀，且常造成误读） |

规则：色板按顺序取前 k 个颜色，不要跳着取。

### 可辨识性自检

用感知色差判断两种颜色是否会被混淆：

| 情况 | 判定 |
|---|---|
| deltaE < 12 | 会被混淆，必须换 |
| deltaE 12–20 | 临界，建议换 |
| 灰度亮度差 L* < 10 | 灰度打印会糊在一起，必须换 |

如果图里塞了超过 ~6 条线或 6 个系列，**拆图**，不要继续加颜色。

### 不确定性

- 必须写明误差条表示什么：SD / SE / CI / 仪器检索精度 / 基线误差 / 系统偏差。
- 必须写明样本量或重采样单位（按轨道？按日？按事件？）。
- **平滑后的点不是独立样本**，不要在图上按点数显示"样本量"。
- **误差条重叠不能单独证明不显著**，不要用它当显著性论证。

### 检查清单

- [ ] 图里的数字与正文、摘要三处一致。
- [ ] 坐标轴有物理量与单位，坐标范围与刻度明确。
- [ ] 颜色有两个以上通道承载信息；只用颜色的地方已修正。
- [ ] 灰度打印后仍能分辨全部系列。
- [ ] 图例覆盖每个系列，没有"其他"这种含糊项。
- [ ] 误差条含义、样本单位、平滑、零线、参考线、显著性标记都有说明。
- [ ] 对数轴、归一化、标准化已明示。
- [ ] 缺测处断开，没有连线穿越。
- [ ] 没有截轴或缩放来夸大效应。
- [ ] 地图类图件写清投影、坐标类型、高度/纬度/地方时约定。
- [ ] 子图编号与正文引用一致。
- [ ] 图注自足：不看正文也能看懂这张图在说什么。
- [ ] **这张图被人眼实际看过**，不是"文件存在所以通过"。

## 四、图注怎么写

图注要能让读者独立看懂，通常包含：

1. **画的是什么**（一句话，不要"类似于……"这种比喻开头）。
2. **数据来源**（仪器、数据集、时间范围）。
3. **处理**（筛选、质控、平滑、分箱）。
4. **符号与编码含义**（颜色、形状、线型、误差条、阴影）。
5. **样本量或重采样单位。**
6. **必要的限定**（是否概念示意、是否经过插值）。

不要把结论写进图注，也不要在图注里做超出数据的推测。

## 五、三线表（如果目标期刊要求）

机械转换步骤，不要手改：

1. 列格式 `{|l|c|c|}` → `{lcr}`（去掉竖线）。
2. 首条 `\hline` → `\toprule`。
3. 表头后的 `\hline` → `\midrule`。
4. 末条 `\hline` → `\bottomrule`。
5. 表内 `\hline` → `\addlinespace`。
6. 表内不用竖线，不用双线。
7. 不用 `\resizebox{\columnwidth}{!}{...}` 强塞宽度；按列宽缩减阶梯处理。
8. 表内不放 `\footnote`，需要表注用 `threeparttable`。

**数字的改动是作者的决定，不是排版的副产物。** 转换过程中如果发现数字可能需要改，停下来问作者，不要顺手改。

## 六、图的迭代上限

- 每张图最多 3 轮修改。
- 第 3 轮仍不满意：说明问题在内容不在图。回去改论证或改数据结构。
- 记录每轮改了什么、为什么，避免无限循环。

## 七、开篇主视觉图：Graphical Abstract（2.5D isometric）

### 定位

放在论文最前面（Graphical Abstract 位置，或正文第一张图）的"一眼看懂"主视觉。它是原理示意图的**故事版**——用 2.5D 等轴测微缩模型，把整篇论文的核心系统/机制讲成一个画面。它不替代、也不竞争科研线路图、原理示意图、数据图；是三件套之外的"门面"。

**时机：必须等整篇文章定稿、数字和结论锁死后再画，不在写作过程中提前画。** Graphical Abstract 是收尾工序，不是草稿期装饰——内容还在改，主视觉画了也白画，还会把一个未定稿的机制先画成"已经定了"。正文、数据图、结论都冻结后，再回到这一节走流程。

**不是每篇都需要。** 综述、短篇、以数据为主的文章可以不做；没有值得画成画面的机制或系统，就别硬塞——图注里写一句"本研究无需主视觉图"，比凑一张好看的空壳更诚实。

风格骨架锚点：[`assets/ga-reference-isometric.svg`](../assets/ga-reference-isometric.svg)。

### 第一纪律：图不替字，关系必指，不许编造

这是 2.5D 生成图最容易翻车、也最伤论文可信度的地方，**优先级高于一切美观要求**。四条，缺一不可：

1. **图标不替文字。** 每个具名实体旁边必须贴明确的文字标签（仪器名、物理量、过程名）。不许靠"画个发光球、画座塔，读者自然懂这是什么"——读者懂不懂全靠猜，猜错就是误导。图标只是辅助识别，**文字标签才是实体本身**；一个没标字的实体，等于没画。
2. **关系必画箭头。** 任意两个实体之间的任何联系（能量流、信息流、因果、传输、观测），必须画成一根箭头，**从 A 明确指向 B**，箭头方向 = 关系方向。不许"两个东西挨得近就暗示它们有关"，也不许画一根没头没尾的装饰性流线。
3. **不许编造。** 图上出现的每一个实体、每一根箭头，都必须能在蓝图/论文里找到出处。蓝图没列的实体不许加，蓝图没写的关系不许画。AI 出图时为了好看自由发挥出来的元素（一个多余的雷达、一条多余的环流、一个论文里没有的参数），**一律删掉，宁可画面空一点**。渲染器的职责是"把蓝图画好看"，不是"替论文发明内容"。
4. **箭头两端都要具名，逐根核对。** 出图后逐根箭头检查三件事：它从**谁**出发、指向**谁**、旁边的字写的是**谁**——三者必须是同一个东西。不允许有断头箭头、不知从哪来的神秘箭头、指向空白的箭头。

> 一句话：**图是用来把已经写定的事实画清楚的，不是用来暗示、猜测、或替论文补内容的。**

### 风格基因（必须同时满足）

1. **视角**：2.5D 等轴测（isometric）斜俯视，物体带垂直厚度——是微缩模型，不是平面框图，也不是照片级渲染；
2. **白底 + 斜切平行四边形平台**，可分层堆叠（单系统 → 多体互联 → 机制层）；
3. **每个核心实体都是微缩立体图标**，绝不允许无意义色块——与本模块"每个形状必须具名"的铁律一致；
4. **彩色粗流线箭头表示"流"**，颜色编码不同类型（电 / 信息 / 物质 / 因果……），箭头方向 = 流向；
5. **右下角集中 Legend**，颜色与线型一一对应；
6. 英文无衬线短标签直接贴在元素旁；扁平 + 轻投影；
7. 整张图本身就是一句机制故事，**但故事里的每个名词、每根连线都必须在论文里有出处**（回到第一纪律）；
8. **图注必须标 "Conceptual illustration"**，绝不能让人误以为是观测或数据图。

### 两阶段流程：Logic → 人审 → Render

**先定逻辑，再出图，不许一步到位。**

**阶段 1 · 架构师：出视觉蓝图（只写文字，不出图）**

从摘要、`claim-map.json`、核心术语里抽出槽位，写成一张蓝图：

- **实体清单 3–6 个**（研究对象、数据来源、方法、关键过程、输出），每个写清它对应论文里的哪一句；
- **箭头清单（必须逐条列，不能只说"有流"）**：起点实体 → 终点实体 → 这根箭头代表什么（能量输入 / 极区加热 / 全球响应 / 观测测量……），每根指定一个颜色；
- 叙事结构三选一：输入→过程→输出 / 微观→中观→宏观 / 左问题-中方法-右结果；
- **禁区清单**：明确写出"论文里没有、不许画进去的东西"（例如没研究的纬度带、没用到的雷达、没做的反馈过程）。
- **素材选型（治"太 AI"，必填）**：每个实体到下节"素材源"里指定**一个具体元件**（名称 + 来源 + 许可），不许只写"画个卫星"。卫星长什么样、雷达长什么样、地球怎么画，都要有据可查，不许让模型凭空脑补。

蓝图先给作者看一眼：实体对不对？箭头连得对不对？素材选得对不对、能不能商用？有没有把论文根本没做的东西画进去？这一步错了，图再美也是错的。

**阶段 2 · 渲染器：出图**

用绘图 skill（图生图 / 文生图），把蓝图 + **已选定的素材元件** + 风格锚点 `ga-reference-isometric.svg` 一起喂进去。**以选定素材为造型依据，只做重排、统一画风、上色、加箭头；不许让模型凭空新发明造型。** 蓝图和素材清单里没有的实体、箭头、装饰，一样都不许自己加。

### 素材源：先备料，再渲染（治"太 AI"）

之前出过的主视觉图"一眼 AI"，根因不是提示词不够华丽，而是**没有可核对的造型来源，全靠模型脑补**——它画的卫星长这样、雷达长那样，都是猜的。根治办法：渲染前先备料。

**允许的免费可商用素材源**（按优先级）：

| 源 | 许可 | 用什么 |
|---|---|---|
| unDraw（undraw.co） | 免费可商用，无需署名 | 扁平 2.5D 人物/场景/通用概念插画，可整支改色 |
| Tabler Icons（github.com/tabler/tabler-icons） | MIT，6100+ 图标 | 卫星、地球、雷达、数据、服务器等线性 SVG 元件 |
| Lucide（lucide.dev；本仓库 `skills/ppt/assets/lucide-*.png` 已内置一份） | ISC | 与 Tabler 互补的线性图标 |
| NASA Image and Video Library（images.nasa.gov） | NASA 作品多为公有领域 | 卫星、地球、极光、空间天气的真实素材——空间物理论文首选 |
| Wikimedia Commons | 逐件看许可（CC0 / PDM / CC-BY） | 仪器示意图、坐标/地理参考；CC-BY 的必须署名 |

**禁止**：

- 不许直接抓 Freepik / Adobe Stock / 视觉中国 / 稿定等需署名或付费图库的图，也不许把它们带水印的预览图喂给模型"学风格"；
- 不许用模型自由发挥"画一个看起来像卫星的东西"替代真实选型；
- 用了 CC-BY 素材必须在图注或致谢里署名；CC0/PDM 也要留一句来源记录（来源、URL、许可），方便审稿时核查。

**备料纪律**：蓝图阶段就要把"实体 → 素材元件 → 来源 → 许可"这一列写全，素材和蓝图一起给作者审。审完再渲染——没备料，不开画。

### 画后四轴审查（人眼必过）

生成图十张有九张有问题，逐轴过一遍：

| 轴 | 怎么判 |
|---|---|
| ✅ 实体对不对 | 图上每个具名东西，和蓝图/论文是不是同一个对象？有没有张冠李戴？有没有蓝图之外冒出来的多余元素？ |
| ❌ 关系通不通 | 逐根箭头查：起点、终点、边上的字三者是否一致？有没有断头箭头、神秘来源箭头？箭头方向和论文的因果方向一致吗？ |
| ⚠️ 标签/文字 | **生成图的英文标签大概率拼错或乱码**（纵轴单位、坐标轴标题最常抽风）——标签、单位、Legend 一律后期叠加干净文字，不指望生成模型自己写对 |
| ❓ 不确定的 | 拿不准的地方标出来问作者，**不替作者猜**；论文里没写死的连接，宁可不画 |

### 三条硬禁令

- 不画真实期刊 logo、真实机构标识、真实品牌；
- 不要廉价蓝紫科技背景、PPT 风、电商海报感、游戏 CG 式发光；
- 不为了好看改科学：箭头接错、实体画错、把没做的步骤画进去、用视觉隐喻代替文字标签，比没有图更糟。

### 来源借鉴

本节是读了三个同类项目后只取可迁移的做法写成的：AIA（Logic 蓝图 → 人审 → Render 两阶段）、scientific-visual-skills 的 `scientific-paper-figure`（内容槽位 + 叙事结构 + 配色系统 + 生成前自检）、surgical-illustration（画前约束 prompt、画后四档审查、不确定就标给人定）。第一纪律（图标不替文字、关系必指箭头、不编造实体与连接）来自一次实际出图后发现的问题：AI 会自由发挥出论文里没有的箭头和元素、用图标代替明确标签。不搬它们的代码，只搬流程纪律，并与本项目"不编结果、不硬塞图、人眼必过"的原则对齐。
