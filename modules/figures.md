# 图：一张路线图、一张原理图、一批数据图

[返回首页](../README.md) · [阶段总控](phases.md) · [同类对比来源](../docs/PEER_COMPARISON.md)

**每个研究任务默认产三张图，一张都不能省：**

1. **科研线路图（roadmap）** —— 你从数据走到结论的路径。给读者看"你干了什么"。
2. **原理示意图（schematic）** —— 你研究的机制或方法长什么样。给读者看"这件事为什么这样发生"。
3. **数据图（data figure）** —— 真实结果的定量呈现。给读者看"数字是什么"。

先打个比方。

**像给朋友指路。** 线路图是"导航路线"——从家到餐厅，几个路口，左转右转。原理图是"餐厅长什么样"——进门是前台，左边是厨房，你的桌子在窗边。数据图是"菜单上的价格"——具体多少钱。

三张图各回答一个问题，谁也不能替代谁。**把价格画进路线图里，就是把两件事混在一起。**

## 一、科研线路图（roadmap）

### 什么时候画

P1 画出草图（回答"打算怎么做"），P4 定稿（回答"实际怎么做的"）。**两版要分开存**，投稿前对照检查，计划与实际的差异要么补做，要么说明。

### 图里必须有的东西

| 要素 | 说明 |
|---|---|
| 数据来源 | 仪器、数据集、时间跨度、空间覆盖 |
| 处理链 | 每一步筛选、质控、坐标转换、分箱 |
| 分析 | 方法名与实际参数 |
| 输出 | 结果量、图件、统计 |
| 结论 | 从哪个结果得到哪个结论 |
| 分叉 | 试过的替代设置，以及为什么保留/放弃 |

### 硬规则

- **每个形状都必须代表一个具名事物。** 不允许出现"抽象的彩色方块"充当装饰或占位。一个方块如果没法命名，就删掉。
- **方向必须唯一。** 图上流动的方向要一致（左→右 或 上→下），不要两种混用。
- **形状词汇固定**：过程 = 矩形，数据/存储 = 圆柱，判断 = 菱形，外部输入 = 圆角矩形。同一篇论文里不能换。
- **层级要一致。** 同一张图里，不能一边画到"载入 CSV"这种粒度，另一边只写"完成分析"这种粒度。
- **主路径加粗，替代路径虚线。** 读者一眼就知道主干在哪。
- **文字最小 8 pt（印刷尺寸下）**，白底，浅色/灰度打印仍能读。
- **写清楚哪部分是你做的、哪部分用的是别人的数据或方法**。用不同边框样式区分，不要靠颜色。

### 检查清单

- [ ] 每个形状都能说出它的名字和含义。
- [ ] 主线路径唯一且连续，没有断头路。
- [ ] 计划版与实际版的差异已比对过，差异有解释。
- [ ] 替代设置画在图上，不是只写在正文里。
- [ ] 缩小到单栏宽度后最小字号仍 ≥8 pt。
- [ ] 转灰度后仍能分辨层次（不依赖颜色区分）。
- [ ] 图注能独立看懂：数据来源、处理、方法、输出都标了。

## 二、原理示意图（schematic）

### 先选原型

按内容选一种，不要混着画。

| 原型 | 什么时候用 | 典型位置 |
|---|---|---|
| 架构图 | 展示系统/模型的分层结构 | Methods 或引言末 |
| 流程图 | 展示机制的时间顺序 | Discussion |
| 组件图 | 展示一个量的构成与来源 | Methods |
| 概念图 | 展示抽象概念之间的关系 | Introduction |
| 对比图 | 并排展示两种条件/两种机制 | Discussion |
| 分类图 | 展示类型划分 | Introduction 或 Discussion |
| 部署/观测构型图 | 展示仪器几何、观测几何 | Methods |

### 机制图必须区分的层级

如果图里画的是机制（"热量怎么传""风怎么吹"），**必须用视觉方式区分证据等级**：

| 层级 | 视觉表达 |
|---|---|
| 已观测到 | 实线箭头 + 实心图形 |
| 推断 | 虚线箭头 + 空心图形 |
| 假说 | 点线箭头 + 问号标记 |

三层不区分，就是拿推断冒充观测。这是机制图最常见的严重问题。

### 硬规则

- **概念图必须标为"概念示意"**，在图注里明说。绝不能让人误以为是观测结果或数据图。
- **不要硬塞 AI 生成图。** 有些论文不需要示意图，图注里说明为什么不需要比硬凑一张好。
- **不允许用颜色块代替命名。** 每个形状都要有文字标签。
- **跨图一致性**：同一篇论文里的所有示意图，配色语义必须锁定（同一个颜色永远指同一件事）；字体、线宽、节点形状统一；组件命名一致；同一抽象层级的图复杂度相近。
- **矢量格式输出**，便于期刊排版。
- **最多迭代 3 轮**。第 3 轮还讲不清楚，说明你的机制本身没想清楚，回去改文字，不要继续调图。

### 检查清单

- [ ] 选定的原型与内容匹配。
- [ ] 机制层级（观测/推断/假说）用视觉方式区分了。
- [ ] 图注写了"概念示意"。
- [ ] 每个形状都有具名标签，没有纯装饰元素。
- [ ] 与同篇其他图的配色语义、字体、线宽一致。
- [ ] 数据墨水比合理：没有为了好看而加的无信息元素。
- [ ] 矢量输出，印刷尺寸下文字 ≥8 pt。

## 三、数据图（data figure）

### 数据从哪来

只从真实结果文件出图。**不准用生成式工具造数据图。** 手工编辑过数字的结果文件不能作为绘图输入。

### 必须留档的东西

源数据、绘图脚本、参数、坐标轴与色条范围、掩膜与缺测处理、图注文本、PNG 与矢量两种输出。

### 颜色：不要只用颜色传信息

这是本模块最重要的一条。**永远不要把信息只编码在色相里。** 色盲读者、灰度打印、屏幕偏色都会把它毁掉。

颜色必须配一个第二通道：

- 标记形状（圆/方/三角）
- 线型（实线/虚线/点线）
- 填充纹理（斜线/点阵）
- 直接标注（把标签贴在线上，而不是只放图例）

### 配色选择

| 用途 | 推荐 |
|---|---|
| 分类（≤8 类） | 优先无障碍色板：`okabe-ito`（8 色，首选）、`tol-bright`（7 色）、`tol-muted` / `tol-light`（9 色）、`tol-high-contrast`（3 色，灰度安全） |
| 顺序 / 发散 | `viridis`、`cividis`、`magma` |
| 不要用 | 彩虹色 `jet` / `rainbow`（感知不均匀，且常造成误读） |

规则：色板按顺序取前 k 个颜色，不要跳着取。

### 可辨识性自检

用感知色差判断两种颜色是否会被混淆：

| 情况 | 判定 |
|---|---|
| deltaE < 12 | 会被混淆，必须换 |
| deltaE 12–20 | 临界，建议换 |
| 灰度亮度差 L* < 10 | 灰度打印会糊在一起，必须换 |

如果图里塞了超过 ~6 条线或 6 个系列，**拆图**，不要继续加颜色。

### 不确定性

- 必须写明误差条表示什么：SD / SE / CI / 仪器检索精度 / 基线误差 / 系统偏差。
- 必须写明样本量或重采样单位（按轨道？按日？按事件？）。
- **平滑后的点不是独立样本**，不要在图上按点数显示"样本量"。
- **误差条重叠不能单独证明不显著**，不要用它当显著性论证。

### 检查清单

- [ ] 图里的数字与正文、摘要三处一致。
- [ ] 坐标轴有物理量与单位，坐标范围与刻度明确。
- [ ] 颜色有两个以上通道承载信息；只用颜色的地方已修正。
- [ ] 灰度打印后仍能分辨全部系列。
- [ ] 图例覆盖每个系列，没有"其他"这种含糊项。
- [ ] 误差条含义、样本单位、平滑、零线、参考线、显著性标记都有说明。
- [ ] 对数轴、归一化、标准化已明示。
- [ ] 缺测处断开，没有连线穿越。
- [ ] 没有截轴或缩放来夸大效应。
- [ ] 地图类图件写清投影、坐标类型、高度/纬度/地方时约定。
- [ ] 子图编号与正文引用一致。
- [ ] 图注自足：不看正文也能看懂这张图在说什么。
- [ ] **这张图被人眼实际看过**，不是"文件存在所以通过"。

## 四、图注怎么写

图注要能让读者独立看懂，通常包含：

1. **画的是什么**（一句话，不要"类似于……"这种比喻开头）。
2. **数据来源**（仪器、数据集、时间范围）。
3. **处理**（筛选、质控、平滑、分箱）。
4. **符号与编码含义**（颜色、形状、线型、误差条、阴影）。
5. **样本量或重采样单位。**
6. **必要的限定**（是否概念示意、是否经过插值）。

不要把结论写进图注，也不要在图注里做超出数据的推测。

## 五、三线表（如果目标期刊要求）

机械转换步骤，不要手改：

1. 列格式 `{|l|c|c|}` → `{lcr}`（去掉竖线）。
2. 首条 `\hline` → `\toprule`。
3. 表头后的 `\hline` → `\midrule`。
4. 末条 `\hline` → `\bottomrule`。
5. 表内 `\hline` → `\addlinespace`。
6. 表内不用竖线，不用双线。
7. 不用 `\resizebox{\columnwidth}{!}{...}` 强塞宽度；按列宽缩减阶梯处理。
8. 表内不放 `\footnote`，需要表注用 `threeparttable`。

**数字的改动是作者的决定，不是排版的副产物。** 转换过程中如果发现数字可能需要改，停下来问作者，不要顺手改。

## 六、图的迭代上限

- 每张图最多 3 轮修改。
- 第 3 轮仍不满意：说明问题在内容不在图。回去改论证或改数据结构。
- 记录每轮改了什么、为什么，避免无限循环。

## 七、开篇主视觉图：Graphical Abstract（2.5D isometric）

### 定位

放在论文最前面（Graphical Abstract 位置，或正文第一张图）的"一眼看懂"主视觉。它是原理示意图的**故事版**——用 2.5D 等轴测微缩模型，把整篇论文的核心系统/机制讲成一个画面。它不替代、也不竞争科研线路图、原理示意图、数据图；是三件套之外的"门面"。

**不是每篇都需要。** 综述、短篇、以数据为主的文章可以不做；没有值得画成画面的机制或系统，就别硬塞——图注里写一句"本研究无需主视觉图"，比凑一张好看的空壳更诚实。

风格骨架锚点：[`assets/ga-reference-isometric.svg`](../assets/ga-reference-isometric.svg)。

### 风格基因（必须同时满足）

1. **视角**：2.5D 等轴测（isometric）斜俯视，物体带垂直厚度——是微缩模型，不是平面框图，也不是照片级渲染；
2. **白底 + 斜切平行四边形平台**，可分层堆叠（单系统 → 多体互联 → 机制层）；
3. **每个核心实体都是微缩立体图标**，绝不允许无意义色块——与本模块"每个形状必须具名"的铁律一致；
4. **彩色粗流线箭头表示"流"**，颜色编码不同类型（电 / 信息 / 物质 / 因果……），箭头方向 = 流向；
5. **右下角集中 Legend**，颜色与线型一一对应；
6. 英文无衬线短标签直接贴在元素旁；扁平 + 轻投影；
7. 整张图本身就是一句机制故事，不看文字能猜出系统怎么转；
8. **图注必须标 "Conceptual illustration"**，绝不能让人误以为是观测或数据图。

### 两阶段流程：Logic → 人审 → Render

**先定逻辑，再出图，不许一步到位。**

**阶段 1 · 架构师：出视觉蓝图（只写文字，不出图）**

从摘要、`claim-map.json`、核心术语里抽出槽位，写成一张蓝图：

- 核心实体 3–6 个（研究对象、数据来源、方法、关键过程、输出）；
- 核心交互/流 2–4 类，每类指定一个颜色；
- 叙事结构三选一：输入→过程→输出 / 微观→中观→宏观 / 左问题-中方法-右结果；
- 关键视觉元素清单，每个都能说清"它代表论文里的什么"。

蓝图先给作者看一眼：实体和流对不对？有没有把论文根本没做的东西画进去？这一步错了，图再美也是错的。

**阶段 2 · 渲染器：出图**

用图生图工具，把蓝图 + 风格锚点 `ga-reference-isometric.svg` 一起喂进去。**只借风格，不抄别人的具体内容。**

### 画后四轴审查（人眼必过）

生成图十张有九张有问题，逐轴过一遍：

| 轴 | 怎么判 |
|---|---|
| ✅ 实体对不对 | 图上每个具名东西，和蓝图/论文是不是同一个对象？有没有张冠李戴？ |
| ❌ 机制通不通 | 箭头方向、连接关系、因果顺序和论文一致吗？ |
| ⚠️ 标签/文字 | **生成图的英文标签大概率拼错或乱码**——标签和 Legend 一律后期叠加干净文字，不指望生成模型自己写对 |
| ❓ 不确定的 | 拿不准的地方标出来问作者，**不替作者猜** |

### 三条硬禁令

- 不画真实期刊 logo、真实机构标识、真实品牌；
- 不要廉价蓝紫科技背景、PPT 风、电商海报感、游戏 CG 式发光；
- 不为了好看改科学：箭头接错、实体画错、把没做的步骤画进去，比没有图更糟。

### 来源借鉴

本节是读了三个同类项目后只取可迁移的做法写成的：AIA（Logic 蓝图 → 人审 → Render 两阶段）、scientific-visual-skills 的 `scientific-paper-figure`（内容槽位 + 叙事结构 + 配色系统 + 生成前自检）、surgical-illustration（画前约束 prompt、画后四档审查、不确定就标给人定）。不搬它们的代码，只搬流程纪律，并与本项目"不编结果、不硬塞图、人眼必过"的原则对齐。
