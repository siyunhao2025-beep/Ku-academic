# 讲解版 Word：把论文讲给不是专家的你听

[返回首页](../README.md) · [阶段总控](phases.md) · [大白话引导](../assets/plain-language-prompts.md) · [审稿人评审](reviewer-panel.md)

**文章写完之后，另外交一份 Word，专门用来把人讲懂。** 它不替代论文，它是论文的**翻译件**。

先打个比方。

**像医生写给你的病历解释。** 病历上写的是"窦性心动过速，心率 112 bpm"，解释页上写的是"你的心跳偏快，大概每分钟 112 下；可能的原因有几种，目前查到的只有一种"。**两份都是真的，但只有第二份是给你看的。**

---

## 一、这份 Word 和论文有什么不同

| | 论文 | 讲解版 Word |
|---|---|---|
| 读者 | 同行审稿人 | 你自己、导师、合作者、以及不懂这个方向的家人朋友 |
| 语言 | 领域术语 | 先打比方，再上术语 |
| 目的 | 证明你做对了 | 让你明白你到底做了什么 |
| 数据 | 全部数据 | **只保留理解结论所必需的** |
| 篇幅 | 按期刊要求 | 按"讲清楚"要求，通常 3–8 页 |

**关键约束：这份 Word 里的每一个数字、每一条结论，必须与论文完全一致。** 它只能换说法，不能换事实。任何在简化过程中被削弱的限定条件，都必须写回来。

---

## 二、固定结构（七节）

脚本生成的骨架就是下面这七节，顺序不要改：

| 节 | 回答什么问题 | 写法要求 |
|---|---|---|
| 1. 一句话结论 | 这项研究到底说了什么 | 一句话，不含术语。**必须同时写出"没有回答什么"** |
| 2. 为什么要做这件事 | 之前的人做到哪一步、缺口在哪 | 用"以前大家以为……实际上……"的对照讲，不列文献清单 |
| 3. 你是怎么做的 | 数据从哪来、怎么处理、做了什么分析 | 每步先用一句大白话，再给术语和参数 |
| 4. 你得到了什么 | 主要结果 | **给数值和条件**，不要"显著提高"这种词 |
| 5. 这些结果说明什么 | 你能下的结论 | 严格区分「观测到」「与……一致」「机制推断」，三级分开放 |
| 6. 有什么限制 | 哪些边界会改变解释 | 只写**真正影响解释**的，不写泛泛的免责声明 |
| 7. 术语表 | 出现的专业词 | 每个词一句人话解释，不抄教科书定义 |

## 三、怎么用

```bash
python scripts/ooxml.py docx <spec.json> <out.docx>
```

`spec.json` 结构：

```json
{
  "title": "讲解版：你的研究讲了什么",
  "blocks": [
    {"kind": "h1", "text": "一句话结论"},
    {"kind": "p", "text": "在……条件下，目标量发生了……；本研究没有回答……"},
    {"kind": "callout", "label": "注意", "text": "这句话里的限定条件不能删"},
    {"kind": "h1", "text": "为什么要做这件事"},
    {"kind": "quote", "text": "以前大家以为……"},
    {"kind": "p", "text": "实际上……"},
    {"kind": "h1", "text": "你是怎么做的"},
    {"kind": "numbered", "marker": "1.", "text": "先拿到……数据"},
    {"kind": "bullet", "text": "关键参数：……"},
    {"kind": "h1", "text": "你得到了什么"},
    {"kind": "table", "rows": [["量", "条件", "数值"], ["……", "……", "……"]]},
    {"kind": "h1", "text": "这些结果说明什么"},
    {"kind": "h1", "text": "有什么限制"},
    {"kind": "h1", "text": "术语表"},
    {"kind": "kv", "key": "基线", "text": "用来做对比的“平时状态”，它的定义变了，结论也会变"},
    {"kind": "pagebreak"},
    {"kind": "h1", "text": "附：与论文的对应关系"},
    {"kind": "table", "rows": [["本页说法", "论文位置"], ["一句话结论", "Abstract / Conclusion"]]}
  ]
}
```

支持的块类型：`title` `h1` `h2` `h3` `p` `bullet` `numbered` `quote` `callout` `table` `kv` `spacer` `pagebreak`。

生成后会自动校验并打印报告：

```json
{"parts": 5, "problems": [], "ok": true}
```

`problems` 非空就说明文件坏了，**不要交付**。

## 四、为什么不用 python-docx

**因为不需要。** 一个 `.docx` 本质上就是一个装着 XML 的 zip：`[Content_Types].xml`、`_rels/.rels`、`word/document.xml`、`word/styles.xml` 加上它们的关系文件。上面要做的事情——标题、段落、要点、引用、提示框、表格——用直接写 XML 就能覆盖。

为一个"把文字放进段落"的需求引入一个依赖包，是精简模式 [阶梯](lean-mode.md) 里明确要避免的。所以 `scripts/ooxml.py` 用标准库 `zipfile` 自己写，约 300 行，且**自带校验**。

**代价是明确的：** 它只支持上面列的那几种块。需要页眉页脚、脚注、公式、目录、自动编号、图片时，它做不到——那时候再考虑引入依赖，或者改用专门的文档工具。这个上限是知情选择，不是遗漏。

**其他已知边界：**

- 输出使用固定时间戳（2026-01-01），因此**同样的输入产生完全相同的字节**，便于校验。代价是文件属性里的创建时间不是真实时间。
- 已存在的同名文件**不会被覆盖**，脚本直接报错退出。这是有意的：防止把上一版讲解稿冲掉。
- 不生成目录、不做拼写检查、不做分页优化。

## 五、绝对不许做的事

- **不许在这份 Word 里出现论文没有的结论。** 它只翻译，不发明。
- **不许为了好懂而删掉限定条件。** 把"在冬季、60–90 km 范围内"简化成"一般情况下"是**改事实**，不是简化语言。
- **不许把关联写成因果。** 论文写"与……一致"，这里也必须写"跟……对得上，但不能证明是它导致的"。
- **不许用"专家认为""研究表明"这种没有出处的说法。**
- **不许把它当成投稿材料。** 它是给你自己看的，不是给期刊的。

## 六、检查清单

- [ ] 七节齐全，顺序未改。
- [ ] 第一节同时写了"没有回答什么"。
- [ ] 所有数字与论文一致（**建议逐项对照，不要凭记忆**）。
- [ ] 每个术语都有解释，且解释是人话不是教科书定义。
- [ ] 观测 / 一致 / 机制推断三级在措辞上分开。
- [ ] 限制一节写的是**真的会影响解释**的限制。
- [ ] 生成报告的 `problems` 为空。
- [ ] 附了"与论文的对应关系"表，方便核对。
