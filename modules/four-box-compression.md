# 阶段2/3 · 四箱分箱、事实锁与压缩

[返回首页](../README.md) · [写作总调度](paper-orchestrator.md) · 脚本：`scripts/boxes.py`

**目标：上下文要爆的时候能把稿子压小，但压完的稿子一个字都不能错。**

先打个比方。

**像出门带行李箱。** 箱子装不下时，你会把毛巾卷起来塞进缝里——但**护照、身份证、药、充电器**一个都不能落。压缩上下文也是一样：可以卷毛巾（删背景句），绝不能丢护照（删参数和定义）。

**更关键的一条：** 压缩出来的只是**给模型看的临时副本**。你的原稿永远原样躺在存档里，导出时拿的是原稿。**所以压缩再狠，也不可能损坏你的稿件。**

---

## 一、四个箱子

| 箱 | 名称 | 信息密度 | 压缩上限 | 依据 |
|---|---|---|---|---|
| **A** | 引言箱 | 最低 | **6×** | 背景铺垫多，抽取空间大 |
| **B** | 数据箱 | 中等 | **3×** | 仪器、数据、方法 |
| **C** | 结果箱 | **最高** | **1×（禁止压缩）** | 每句都直接支撑结论 |
| **D** | 结论箱 | 次高 | **2×** | 轻度抽取 |

### 结果箱为什么一个句子都不能动

结果段里「上升 12.5 K」和「在 95 km 处、扰动主相后 6 小时内」是**一体**的。压掉后半句，12.5 K 就变成了一个没有适用范围的数字，结论的边界被悄悄放宽了。

所以 C 箱的规则不是"尽量不压"，是**脚本直接拒绝**：

```text
$ python scripts/boxes.py compress runs/my-paper C --keep 0.5
box C holds the results and is never compressed   (退出码 2)
```

### 压缩纪律

> 压缩**只在箱内执行，不跨箱删句，不打乱段落原有顺序**。

实现上：压缩只做**抽取式**删除——留下来的句子是原文的**逐字拷贝**，并**按原始顺序**拼接。**没有任何改写。**

## 二、三级事实锁

| 锁 | 内容 | 压缩时 | 舍弃时 |
|---|---|---|---|
| 🔴 **红锁** | 样本数量、观测时间、仪器名称、阈值、边界筛选条件、核心物理参数 | **100% 保留** | 不允许舍弃 |
| 🟡 **黄锁** | 次要限定条件、衍生参数 | 空间不足时可舍弃 | **必须输出丢失清单** |
| 🟢 **绿锁** | 背景铺垫、过渡句、重复描述 | 可自由抽取 | 记入丢失清单 |

### 脚本怎么识别红锁

| 模式 | 例子 |
|---|---|
| 数字 + 单位 | `12.5 K`、`95 km`、`6 h` |
| 样本量 | `n = 48` |
| 阈值 | `> 50 nT`、`不超过 3` |
| 时间窗口 | `2020-03-01`、`12:00 UT` |
| 声明的领域术语 | 你在 `domain_keywords` 里填的仪器名与参数名 |

⚠️ **识别是模式匹配，不认识的写法会漏。** 所以 `domain_keywords` 一定要把你论文里用到的仪器名、参数名填全。

### 红锁升级机制（这一条最容易被忽略）

红锁事实常常依赖于某个定义。例如：

> 「扰动幅度是 12.5 K，是安静基线的 3.1 倍。」

12.5 K 是红锁。但**"安静基线"的定义**（前 10 天中位数）如果被压掉，12.5 K 就失去了参照。

**规则：任何定义了「红锁事实所涉及术语」的句子，自动升级为临时红锁。**

脚本实现：

1. 找出所有带红锁事实的句子；
2. 找出所有含定义标记的句子（`定义为` / `是指` / `defined as` / `refers to` …）；
3. 取定义句中**定义标记之前**的被定义主体，提取术语；
4. 如果这些术语出现在红锁句里 → **该定义句升级为临时红锁**。

而且不只是提醒——**`verify()` 会强制执行**：如果定义句消失、而术语仍在被使用，校验直接失败并报 `red_escalated_lost`。

实测（`tests/test_locks.py` 钉住的）：

```text
改前：… quiet baseline level. The quiet baseline is defined as the 10-day median… n = 48 orbits.
改后：… quiet baseline level. n = 48 orbits.          ← 定义句没了
判定：ok = False，red_escalated_lost = ["baseline"]
```

**数字还在，定义没了 —— 拦住了。**

## 三、压缩流水线

```text
1  内容自动/人工归类到 4 个箱子
2  每箱抽取事实三元组 → 生成红/黄/绿锁 → 构建事实依赖图
3  二分搜索：在箱子的倍率上限内，找【红锁 100% 保留】的极限倍率
4  压缩只用抽取式，禁止生成式改写；只删冗余句，不改写语义
5  压缩后校验，输出压缩报告：整体压缩率、红锁召回率、黄锁保留率、丢失条目清单
6  把压缩后的临时文本送入模型推理
7  用户下达【导出完整全文】→ 直接读 4 箱原始存档拼接，完全不使用压缩副本
```

### 二分搜索

目标是在上限内找**最大可行倍率**，可行 = 红锁召回 100% 且不超过箱子上限。

```text
lo = 1.0, hi = cap
每次取 mid，压缩到 1/mid，校验红锁召回
  可行 → lo = mid（还能更狠）
  不可行 → hi = mid
收敛后取可行的最大值，并要求 <= cap
```

**红锁召回是从实际保留下来的文本重新算出来的，不是假设的。** 每次探测的 `ratio` 与 `feasible` 都记进报告，可复核。

实测（四箱内容不同）：

| 箱 | 上限 | 实测最大倍率 |
|---|---|---|
| A 引言箱 | 6.0× | 5.99× |
| B 数据箱 | 3.0× | 2.66× |
| C 结果箱 | 1.0× | 1.00×（禁止压缩） |
| D 结论箱 | 2.0× | 1.99× |

## 四、Token 刹车

实时统计：**历史对话 token + 用户新 query token + 预留输出 buffer**。

| 阈值 | 动作 |
|---|---|
| **80%** | 侧边预警，继续写作 |
| **90%** | **触发紧急刹车**：暂停推理，进入分箱压缩 |

```bash
python scripts/boxes.py budget --window 200000 --history 150000 --query 20000 --reserve 10000
```

```json
{"status": "brake", "used_tokens": 180000, "ratio": 0.9,
 "action": "stop generating, compress the boxes, then continue from the compressed copies"}
```

### ⚠️ 一个必须说清的限制

**本工具读不到对话的 token 计量。** 已实际排查本机的会话记录位置，没有任何一处包含当前对话的用量（详见 [Token 统计口径](../docs/TOKEN_ACCOUNTING.md)）。

所以四个输入（`window` / `history` / `query` / `reserve`）**必须由调用方声明**。缺任何一项，刹车返回：

```json
{"status": "unknown",
 "unknown_inputs": ["history"],
 "action": "cannot decide; supply the missing figures from the platform's usage view rather than estimating them"}
```

**为什么不猜：一个用编出来的数字触发的刹车，比没有刹车更危险。** 它会让你以为自己在安全区里。

**能精确测量的是压缩收益。** 四个箱子的文本量、压缩倍率、红锁召回率全部是实测的。所以"该压多少"这件事是可执行的，只有"现在用了多少"需要你从平台的用量页拿。

## 五、导出完整全文

```bash
python scripts/boxes.py export runs/my-paper --out export/full.md --provenance export/provenance.json
```

**直接读取 4 个箱子的原始未修改存档文本拼接，完全不使用压缩副本，保留论文原有倒三角叙事结构。**

输出会附带来源证明：

```text
exported 10234 characters from original archives only
  A 引言箱    142 sentence(s)  sha 3f2a91c8d4e7
  B 数据箱     98 sentence(s)  sha 88b1c0a4f2d9
  C 结果箱    176 sentence(s)  sha 5c7e2b91a03f
  D 结论箱     61 sentence(s)  sha a1d4f8e2705b
```

`provenance.json` 里每条都写着 `"source": "original_archive"`。

**导出会拒绝覆盖已存在的文件。** 防止把上一版全文冲掉。

## 六、原始存档是不可变的

每箱的原始文本都有 SHA-256 记录。任何**在工具之外**的修改都会被检测到，之后的 `add` 与 `compress` 都会直接报错：

```text
original archive was modified outside this tool; refusing to append   (退出码 2)
```

压缩**从不写原始存档**——它写在同目录下的独立副本文件（如 `compressed-2p66x.md`）。有测试专门断言"压缩前后原始存档逐字节相同"。

---

## 七、压缩模块禁止行为

| # | 禁止 | 实现 |
|---|---|---|
| 1 | 禁止压缩结果箱原文 | ✅ `compress` 对 C 箱直接报错 |
| 2 | 禁止打乱段落顺序、跨箱删除句子 | ✅ 抽取式 + 按原序拼接 |
| 3 | 禁止用压缩副本作为最终论文输出源 | ✅ `export` 只读 `archive_path`，有测试断言源码里不出现 `compressed_path` |
| 4 | 禁止修改红锁事实内容 | ✅ 每次压缩后 `verify`，红锁丢失/改值/新增 → 拒绝输出 |
