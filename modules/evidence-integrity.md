# 文献真实性：先证明这篇文献存在，再证明它支持这句话

[返回首页](../README.md) · [阶段总控](phases.md) · [同类对比来源](../docs/PEER_COMPARISON.md)

**这一模块只做两件事，但两件都必须做。**

第一件：这篇文献**真的存在吗**，出处对不对。
第二件：这篇文献**真的支持我要用它说的那句话吗**。

很多人只做第一件，做完就说"引用已核验"。这是本模块要挡住的主要错误。DOI 能解析，只说明这个编号指向某个记录，**不说明这句话是对的**。

先打个比方。

**像寄快递。** 第一件事是查地址存不存在、门牌号对不对（不然包裹退回来）。第二件事是地址对了，但里面装的是不是收件人要的东西——你寄了一箱苹果，对方要的是螺丝刀，地址再准也是寄错。第一件事做完只叫"地址有效"，不叫"寄对了"。

## 一、身份核验：四态判定

对每一条参考文献，只允许四个结论之一。**没有第五种，也不允许"看起来没问题"这种模糊结论。**

| 判定 | 含义 | 处置 |
|---|---|---|
| `VERIFIED` | 标题、作者、年份、期刊/会议、卷期页、DOI 全部与权威记录一致 | 可用 |
| `MISMATCH` | 文献存在，但至少一个元数据字段对不上（年份错、作者漏、期刊写成会议、卷期页错） | 必须改正后才能用；改不动就删 |
| `UNRESOLVED` | 查不到这条记录，或无法访问权威来源确认 | **按可能杜撰处理**，不得进入正文；标 `待确认` |
| `RETRACTED` | 记录存在但已撤稿、更正或失效 | 不得作为支持证据；如必须提及，须显式说明撤稿状态 |

补充标记 `CANONICAL_INSTANCE`：同一篇文献存在多个版本（预印本 / 正式版 / 会议版 / 更正版）时，标出哪个是应当引用的规范版本。

**核验顺序**

1. 以 **DOI** 为主键。有 DOI 就解析 DOI，不要靠题名搜索。
2. 权威记录优先：出版社官方页面 > Crossref > 其他索引。索引与出版社冲突时以出版社为准。
3. 交叉核对：用第二个独立来源核对标题、作者、年份。两个来源一致才给 `VERIFIED`。
4. 无 DOI 的条目（旧文献、书章、报告）：必须由人实际看到权威页面并确认，且获得作者明确批准后才纳入。**不要凭记忆补一个 DOI。**

**绝对禁止**

- 凭记忆重打元数据。要从来源复制，或让程序解析。记忆里的年份和卷期错得最多。
- 把"搜索结果里出现了"当成"这条引文是真的"。
- 把摘要页当全文页、把预印本当正式版。
- 未读过全文就写"该文指出……"。

## 二、支持核验：六类状态

身份过了之后，判定这条文献对**当前这一句话**的支持程度。

| 状态 | 含义 |
|---|---|
| `SUPPORTS` | 文献直接支持该论断 |
| `PARTIALLY_SUPPORTS` | 支持一部分（部分条件、部分范围、部分结论） |
| `BACKGROUND_ONLY` | 只能提供背景，不能作为该论断的证据 |
| `CONTRADICTS` | 文献的结论与该论断相反 |
| `DOES_NOT_SUPPORT` | 文献说的不是这件事 |
| `CANNOT_VERIFY` | 拿不到足够内容做判断（付费墙、只有摘要、语言不通） |

**硬阻断项：`CONTRADICTS` 和 `DOES_NOT_SUPPORT`。** 出现这两类，句子不能留，必须删掉、改掉或换成真正支持它的文献。不能靠加一个"however"糊过去。

`CANNOT_VERIFY` 需要作者决定：要么删掉这个论断，要么把论断降级到文献可支持的范围。**不要让它默认通过。**

`PARTIALLY_SUPPORTS` 需要改句：把论断收到文献真正覆盖的条件范围内。

### 每条记录要填的字段

| 字段 | 说明 |
|---|---|
| `citation_id` | 引用编号 |
| `location` | 在稿件中的位置（节/段） |
| `claim` | 这一句实际主张什么（照抄，不要转述） |
| `reference_key` | 文献标识 + DOI/PMID |
| `available_evidence` | 实际能拿到什么（仅摘要 / 全文第几页 / 某表某图） |
| `status` | 上表六类之一 |
| `confidence` | 高 / 中 / 低，并说明为什么 |
| `action` | 保留 / 改句 / 换文献 / 删除 / 待作者决定 |

**判定纪律：不要因为题名关键词重叠就推断支持关系。** 题名像不等于说的是同一件事。要看具体结论、条件、范围和数值。

### 范围匹配检查

判定支持关系时，必须逐项比对：

- **对象**：是同一个物理量吗？（温度 vs 温度梯度；风速 vs 风场）
- **范围**：高度、纬度、地方时覆盖对得上吗？
- **条件**：事件强度、事件阶段、静日基线定义一致吗？
- **方法**：是观测、模拟、再分析还是实验室结果？
- **时间尺度**：瞬时、日变化、季节还是年际？

任一项明显不匹配，就不能给 `SUPPORTS`。

## 三、六类高风险错配

以下六种是最常见、也最容易被审稿人抓到的错配。出现任何一种，直接按阻断处理。

| # | 错配类型 | 例子 | 正确做法 |
|---|---|---|---|
| 1 | **把综述当原始实验引用** | "该文观测到 X"——其实是综述里的二手描述 | 引用原始论文；综述只用于概括领域状态 |
| 2 | **用关联证据支持因果** | 时间上同步就写成"A 导致 B" | 只写"与……一致"，或补机制证据 |
| 3 | **把模拟当观测引用** | "观测显示"——其实是模式输出 | 明确写模式/再分析，不写"观测" |
| 4 | **高度/纬度/地方时范围不匹配** | 拿极区冬季结果支持中纬夏季论断 | 换成匹配条件的文献，或收窄论断 |
| 5 | **趋势方向相反** | 文献报告升高，你写降低 | 按文献方向写，或解释差异来源 |
| 6 | **用二手来源给精确数字** | 具体数值取自另一篇论文的转述 | 追溯到原始数据来源；追不到就删掉这个数字 |

## 四、`待确认` 标记怎么用

无法核实的内容**必须显式标注**，不能默默略过，也不能写得像已经核实。

统一写法：

```text
待确认：<要确认什么>。依据：<已查到什么 / 卡在哪>。确认方式：<需要什么>。
```

示例：

```text
待确认：该文报告的关键指标异常幅度（原表 Fig.4）。
依据：正文与该表所在页无法访问，仅摘要提到"显著增温"。
确认方式：获取全文或作者提供图件后填入具体数值。
```

三条纪律：

1. **不要用"约""大概""据报道"伪装确定性。** 有疑问就标出来。
2. **不要把 `待确认` 的条目用在下游论证里。** 它只能出现在待办清单，不能出现在结论链上。
3. **不要把"无法核实"写成"未发现问题"。** 查不了不等于干净。

## 五、输出文件

### `audit/citation-provenance.json`

```json
{
  "citations": [
    {
      "citation_id": "C1",
      "location": "Introduction, paragraph 3",
      "claim": "目标量在条件出现后 6–12 小时发生单调变化",
      "reference_key": "10.1029/XXXX",
      "title": "文献标题（从来源复制）",
      "authors": "从来源复制",
      "year": 2019,
      "journal": "从来源复制",
      "volume_issue_pages": "从来源复制",
      "canonical_instance": "publisher version of record",
      "citation_verdict": "VERIFIED",
      "available_evidence": "full text p.4, Fig.2",
      "support_status": "PARTIALLY_SUPPORTS",
      "confidence": "中：文献覆盖 60–90 km、冬季，未覆盖夏季",
      "action": "改句：把论断收窄到冬季与 60–90 km"
    }
  ],
  "blockers": [],
  "warnings": [],
  "to_confirm": []
}
```

字段约束：

- `citation_verdict` ∈ `{VERIFIED, MISMATCH, UNRESOLVED, RETRACTED}`
- `support_status` ∈ `{SUPPORTS, PARTIALLY_SUPPORTS, BACKGROUND_ONLY, CONTRADICTS, DOES_NOT_SUPPORT, CANNOT_VERIFY}`
- `blockers` 里放所有 `CONTRADICTS` / `DOES_NOT_SUPPORT` / `RETRACTED` / `UNRESOLVED` 条目
- `to_confirm` 里放所有 `待确认` 条目

### 检索日志（与 `modules/literature.md` 共用）

检索的**查询语句、日期、来源、命中数、截断、失败**都要留档。检索失败与零命中分开报告——"没搜到"和"搜不了"完全是两回事。

## 六、验收纪律

下面几句话请当作硬规则记住，它们比任何技巧都重要。

- **解析成功不代表引用正确。** DOI 能开，只过了第一关。
- **部分通过不等于通过（PARTIAL-PASS is not a PASS）。** `PARTIALLY_SUPPORTS` 必须改句，不是打个勾。
- **不要让"没法检查"读成"检查干净"。** 说不清楚就说说不清楚。
- **不要静默决定，不要静默删除。** 每条处置都要留记录。
- **最强结论只能是"可进入人工投稿复核"。** 永远不给录用概率，不给"保证录用"。
- **核验的目的是让判断可追溯，不是给你一个通过章。** 最终科学判断仍然由人做出。
