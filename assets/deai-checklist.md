# 交付前自查表（降 AI + 证据完整性）

[返回首页](../README.md) · [降 AI 模块](../modules/deai-writing.md) · [文献真实性](../modules/evidence-integrity.md)

**用法：** 每次交付润色稿、补稿或整稿修订之前，先跑一遍。答案写下来，不要只在脑子里过。

**顺序不能反：先查证据，再查语言。** 先把科学内容钉死，再谈读起来像不像人写的。

---

## 第一层：证据完整性（最高优先级）

| # | 检查项 | 结果 | 备注 |
|---|---|---|---|
| 1 | 有没有哪句话在修订后变得比原稿更强？逐句核对 `suggests / indicates / demonstrates / is consistent with` 的层级 | | |
| 2 | 数字是否被改动？建议对修订稿做字符级 diff，逐个人工确认 | | |
| 3 | 单位是否被改动或缺失？ | | |
| 4 | 有效位数是否变化？（3.14 不能成 3.1，1.20 不能成 1.2） | | |
| 5 | 正负号、不等号方向是否变化？ | | |
| 6 | 样本量、置信口径（SD/SE/CI）是否变化？ | | |
| 7 | 是否出现了原稿没有的因果表述？（关联被写成了因果） | | |
| 8 | 是否把"计划中的分析"写成了"已完成"？ | | |
| 9 | 仪器名、数据集版本、坐标系统名是否变化？ | | |
| 10 | 引用位置与引用编号是否仍对应？（改句后引用可能错位） | | |
| 11 | 是否出现了无出处的归因（"研究表明""专家认为"）？ | | |
| 12 | 无法核实的内容是否已显式标注 `待确认`？ | | |

**第 1、2、7、8 条中任何一条为"是"，停止交付，回到修订。**

## 第四层：语言清晰度与模式复查

| # | 检查项 | 目标 | 结果 |
|---|---|---|---|
| 38 | 主语、对象、比较项、条件与指代能否一次读清？ | 无需猜测 | |
| 39 | 拆句/合句是否降低理解负担，而非机械制造句长差？ | 每处有清晰度理由 | |
| 40 | 排比或同构句是否承担真实并列/比较功能？ | 无功能则改 | |
| 41 | 段末总结是否增加新信息，而非换词复述？ | 只保留实质解释 | |
| 42 | 加粗与其他强调是否符合目标文档结构？ | 不靠格式制造重要性 | |
| 43 | 模糊结尾是否改成具体边界/可检验问题，或删除？ | 无空泛收尾 | |
| 44 | 无出处归因 | 0 | |
| 45 | 冒号、破折号与标点是否各自承担清楚的逻辑功能？ | 不按配额机械处理 | |
| 46 | 标点与目标语言、期刊规范是否一致？ | 服从真实规范 | |
| 47 | 空泛名词化（"进行了分析""实现了提升"） | 无 | |
| 48 | 过渡语是否连接了真实逻辑，而非只命中词表？ | 无功能则删 | |
| 49 | 结尾意义判断是否有结果或文献支撑？ | 不超主张上限 | |
| 50 | 是否存在只为检测器分数、词表命中数或句长配额而做的改动？ | 0 | |

## 判定

| 结果 | 含义 |
|---|---|
| 第一层有任何一条未过 | **不得交付** |
| 第二层有硬阻断项未清 | **不得交付** |
| 第三层 26、27、37 任何一条未过 | **不得交付** |
| 第四层出现含义不清、术语漂移或检测器导向改写 | 需要撤回相关改动并重做语义审查 |
| 第五层 51 或 52 答不出来 | 内容问题，不是语言问题，回到 P4/P5 重看 |

**最强结论只能是"可进入人工投稿复核"。** 不给录用概率，不给任何保证。

## 记录格式

自查结果建议存为 `audit/deai-selfcheck.md`，格式：

```markdown
# 自查记录
日期：YYYY-MM-DD
被检文件：<文件名>
修订轮次：第 N 轮

## 第一层证据完整性
1. 通过 —— 逐句核对了 23 个证据强度词，未发现增强
2. 通过 —— diff 显示数字改动 0 处
7. 未过 —— 第 3 段"导致"系原稿"伴随"，已改回
...

## 处置
- 第 7 项：已改回原表述
- 第 41 项：删除 2 处只换词复述的段末总结

## 结论
可进入人工投稿复核（第一层已全过；第二层 blockers 已清）
```
